最重要的核心点：
从失败中找问题并分析根因 + 通过迁移其他领域的顶刊顶会方法去解决问题，关键点有两个，第一个是分析根因到底能不能分析出来，就像是之前的固定阻抗控制的例子，第二个更关键，能否找到其他领域的方法进行方法迁移，最关键的三点就是先找到其他领域的问题-干预对，然后判断是否是机制同构，然后自然的迁移/改造。

---------------------
# 01｜ARIS Method Design 科研流程与标准

## 一、核心认知

**从失败中找问题并分析根因 + 通过方法/机制迁移解决问题。**

两个关键能力：

1. **根因到底能不能真正分析出来。**
2. **更关键：能不能主动找到其他领域真正可迁移的方法机制。**

跨领域迁移最关键的三步：

1. 找到真实 **Problem–Intervention Pair**。
2. 判断是否 **Intervention-Level Isomorphism**。
3. 根据 **Target Constraints** 自然迁移/改造。

## 二、唯一目标

优化 Method Design，使 Harness 能真正设计出具有**顶会顶刊核心贡献潜力**的方法。

核心主干：

`Real Failure`
→ `Mechanism-Level Root Cause`
→ `Required Mechanism Change`
→ `主动寻找强 Source Mechanism / Solution Principle`
→ `验证能否迁移`
→ `Target-Constraint-driven Necessary Adaptation`
→ `Minimal Strong Method Seed`
→ `Top-Venue Strength / Causal Validation`

基本原则：

**问题先于方法；机制先于组件；必要性先于创新性；看 causal intervention 而不是表面相似；方法应是最小自然修复；先证伪再确认。**

## 三、Method Genesis

每个方法必须能够解释：

`Failure`
→ `Root Cause`
→ `需要改变什么机制`
→ `为什么想到这个 Source Mechanism`
→ `为什么它真的能迁`
→ `为什么 Target Constraints 要求这样改造`
→ `Final Method`

始终回答三个问题：

1. 为什么想到这个 Source Mechanism？
2. 为什么这个 Source Mechanism 逻辑上真的能迁？
3. 为什么迁移之后会自然形成一个新的强 Method？

## 四、Failure → RCA → RMC

Failure：

`condition → observable failure → consequence`

Failure 必须真实、重要，并位于目标 Operating Envelope 内。

提出新 Method 前先排除合理 Simple Repair。若合理 tuning、标准 estimator/filter/observer、已有 constraint/certificate、容量增加、局部 reparameterization 或 strongest baseline 已能闭合 Failure，则新 Method 的必要性不成立。

RCA 不能停在“泛化差、鲁棒性不足、精度低、不够自适应”等表层描述；必须定位足以解释关键 Failure、且能够被方法干预的主要 causal/computational mechanism，例如：

`state / relation / information path / representation / constraint / observability / computation / optimization / decision structure`

RCA 必须：

* mechanism-level；
* falsifiable；
* evidence-calibrated；
* intervention-relevant；
* 有 competing explanations / falsifier；
* 不先想方法再倒推根因。

RMC 从 accepted residual RCA 推出，明确：

`当前哪个 causal/computational relation/state/information structure`
→ `必须发生什么改变`
→ `change direction`
→ `causal/intervention position`
→ `activation condition`

进一步形成：

`Root Cause → Required Mechanism Change → Required Capability / Design Obligations`

核心原则：

**研究问题决定需要解决什么；根因决定方法应该做什么；具体算法只是实现手段。**

## 五、Source Mechanism 与方法迁移

Source Search 由 RMC 驱动，核心问题：

> **哪个已有机制已经成功改变了我这里必须改变的 causal/computational variable / relation？**

强 Source 必须能够恢复：

`Source Problem`
→ `Source Intervention`
→ `Changed Variable / Relation / Structure`
→ `Mechanism / Causal Effect`
→ `Outcome`
→ `Assumptions / Boundary`

真正迁移的是**方法解决问题的机制，而不是方法表面形式**。

真正的同构核心：

`Target Required Mechanism Change ↔ Source Intervention`

Source Intervention 实际改变的 relation 必须就是 Target RCA/RMC 证明必须改变的 relation，并且 change direction、causal/intervention position、activation condition、actual effect 等正确。

**Source Root Cause 与 Target Root Cause 整体一致不再是硬要求；真正必须同构的是 intervention structure。**

## 六、Target Adaptation 与 Natural Derivation

形成：

`Source Mechanism / Solution Principle`

* `Target Constraints`
  → `Assumption–Constraint Collision`
  → `Necessary Adaptation`
  → `Final Method`

目标域改造由真实 Target Constraints 驱动；**改造大小本身不是创新标准**。没有真实 constraint、assumption mismatch 或 Residual MUST，不为“显得创新”增加模块。

删除全部 Source-domain story 后仍必须成立：

`Target Failure`
→ `Root Cause`
→ `Required Mechanism Change`
→ `Target Constraints`
→ `Final Method`

Final Method 应是从 Target Root Cause 自然推出的**最小、可检验 causal repair program**，而不是 Method Soup。

## 七、Top-Venue Strong Method

`Valid Method Seed ≠ Top-Venue Strong Method Seed`

重点检查：

* Problem Value
* Necessity
* Target Intervention Novelty
* Mechanism Delta
* Scientific / Conceptual Delta
* Closest-Prior Separation
* Causal Coherence
* Minimality
* Natural Derivation
* Claim-Proportional Feasibility
* Discriminative Validation

Novelty 判断 causal intervention / mechanism change，而不是算法名称。

Source primitive 已存在、Source mechanism 成熟或 Target adaptation 小，本身不能否定创新。

Performance gain、算法名、模块数量和复杂度不能代替 Scientific Delta。

Critical scientific FAIL 不能被 weighted score 抵消。

最核心因果一致性：

`Target Required Structural Change`
`= Selected Principle / Source Intervention`
`= Final Method Real Computational Change`

## 八、Evidence、Test 与 Recovery

Discriminating Test 必须区分 Candidate Principle / Rival Principle 或 Primary RCA / Rival RCA，而不是只比较 performance。

Evidence 可以改变 Principle、assumptions、applicability boundary、Target operationalization、Source–Target mapping 或 RCA。

失败应返回真正失效的上游科研环节：Test、mapping、Source、Principle、RMC/RCA、Novelty/Delta 或 Feasibility。

Full Causal Validation：

`predicted mechanism change`
→ `observed mechanism change`
→ `discriminating evidence`
→ `performance consequence`

Performance improvement 本身不能构成 VALIDATED。

## 九、科研标准如何形成

科研标准不能靠理论上“应该如此”直接冻结。

用真实顶级论文恢复 **Method Genesis** 和 **Method Genealogy**，并结合：

`顶级成功案例`

* `同路径近失败案例`
* `必要反事实`
  → `Cross-Case Causal Induction`

区分：

* Necessary Conditions
* Non-Necessary Conditions
* Insufficient Conditions
* Interaction Conditions

不同论文允许不同 formation logic；不强行给每篇论文制造 Root Cause、Source Method 或迁移故事。

最终把经过真实案例验证的科研规律转化为：

**Agent 可执行 → Reviewer 可判断 → Validator 可检查 → Gate 可阻断 → 失败可回退。**
