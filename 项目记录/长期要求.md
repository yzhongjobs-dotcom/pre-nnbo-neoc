# 长期要求与科研判断

## 目标与优先级

用户目标是把既有idea打磨到**顶刊水平**：研究问题、现有方法不足和方法一起迭代，使方法从问题及失效成因中自然产生。B0完整问题和方法是当前打磨起点；后续局部实验没有充分依据撤掉它，也不将B0冻结为不可修订的答案。目标不是保住一组算法名称，也不是仅让程序跑通。

执行顺序为：用户最新明确要求 → 长期科研原则 → 当前有效工作安排 → 历史计划。事实和数学结论依原文、推导、代码和数据判断，不能用指令优先级或文件标题决定真假。

截至2026-10-15，当前任务是精简项目及完成交接；用户尚未启动下一轮科研优化。文件组织不偷偷变成新选题、推导或科研实验。

## 科研workflow

1. 从原idea的科学意图出发理解领域现状，恢复strongest prior的强版本，追问它在什么重要自然条件下受限、为什么受限。
2. 研究问题须有科研价值并符合领域taste：任务后果、困难具体性、强prior边界、潜在认识/能力增量和判别证据。已经被研究不等于已被充分解决；不要求发现一片无人涉及的空白。
3. 锚定问题后，从成因推导机制再选工具。成熟模块可复用，跨领域方法可借鉴。问题、现有方法不足与我们的设计共同打磨，允许依证据调整核心idea。
4. 用最小而有判别力的理论或仿真检查failure及其成因，再查方法是否改变成因、边界在哪里。任务条件来自领域，不为了制造算法优势随意添难。
5. 不利结果先定位受影响层次：实现错修实现，载体遗漏修载体，方法不匹配改方法，问题不准就调整问题。问题与方法可随现状理解和机制证据共同迭代，不必等到问题被严格反证；但每次调整须有对应层次的理由，局部负结果不自动要求缩题。能复用的复用，不能复用的重做。
6. 最终论证：重要问题需要什么能力 → 强方法为什么仍受限 → 方法机制为何由此产生 → 实际推进了什么、边界是什么。

通用控制贡献与超声应用贡献均可审查；不为了躲避一个应用阴性结果转成琐碎数值题，也不强迫通用问题先通过超声指标。

## 必须避免的已发生failure

| 过去的错误 | 今后如何处理 |
|---|---|
| 看到已有工作就避让，逐个检查模块是否全新 | 还原已有能力、继续追问重要边界；评价整项科学进展 |
| 反复要求“必须NNBO/NEOC” | 检验机制是否自然推进问题，不设特定算法不可替代性门槛 |
| 简化任务中固定/简单控制够好，就缩小整个研究问题 | 先检查载体保留了什么，只更新证据支持的结论 |
| 添加约束、目标或未来分支直到算法赢 | 先证明条件和困难来自领域；容量不足不能靠更新器克服 |
| 人为给定理想刚度，再证明提前信息有用 | 让动作由实际任务和动力学生成，查真实观测如何改变决策 |
| 精确节点根被当作优质策略 | 分开根误差、critic域内质量和实际轨迹性能 |
| 原NNBO复现跑通就认为B0固定根已修复 | 明确状态、动作、目标和学习/求根对象之间的变化 |
| 单次50%跳变、昂贵逐候选检查被当作慢变idea否定 | 对准用户场景；B0逐候选认证与事先适用域直接更新是不同部署设计 |
| 物理慢变被当成小描述符步 | 已知空间状态移动、真实场变化、估计修订分别处理 |
| 所有旧记录都搬入新工作区 | 只保留有明确研究或复用用途的材料；教训压缩，原件用Git回查 |

Q3已撤回为主线；值根只是有条件的机制候选；完整wrench退化核对只是附录已有边界的复核。均不可在后续接手时重命名为新问题或新发现。

## 执行与证据

沟通用准确简洁的人话。报告具体改动、原因、验证及限制；不要让用户反复阅读库存清单，不堆文档，不将整理量当科研进展。只在需要时阅读相关历史，不把全套检查当成每次工作的门槛。
