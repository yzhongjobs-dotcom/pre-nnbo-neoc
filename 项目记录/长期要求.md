# 长期要求与科研判断

本文件保存用户确认的稳定目标、科研流程与判断标准。当前方案见[HANDOFF](HANDOFF.md)，具体证据与历史教训见[研究决策与变更](研究决策与变更.md)。

## 一、目标与判断标准

目标是一篇有实质科学贡献、证据足以参与顶刊竞争的论文。共同打磨研究问题、现有方法的不足和方法设计，重点判断：

- **问题有分量：** 具体、重要，能够说明解决后改变什么能力或认识；既不抽象空泛，也不缩成一个求解器的小改进。
- **方法有实质进展：** 相对领域充分已有能力，解释清楚靠什么机制解决了什么重要困难。成熟机制的复用、迁移和小改造均可能产生贡献。
- **证据支持贡献：** 理论、对照与任务实验支撑所声称的能力，说明条件、成本与边界。流程完成、模块数量和局部胜率不代表顶刊水平。

以上吸收了[顶刊论文独立逆向分析](../研究/顶刊论文问题与方法设计_独立逆向分析.md)的有效认识，不是统一录用清单；不设固定提升百分比、模块原创量或定理数量。

## 二、科研流程及每一步的标准

| 步骤 | 怎么做 | 判断标准 |
|---|---|---|
| **1．理解领域现状** | 围绕核心问题阅读相关原文，梳理技术路线、强方法的充分能力、成立条件与代价；针对关键疑问持续检索并更新现状。 | 准确说明已有方法能做到什么、为什么仍值得研究；不止列论文和作者自述局限，不为支持预设方案选择性取证。 |
| **2．凝练重要问题** | 从实际需求、目标冲突、现有能力边界和第一性原理深入追问；既研究领域公认难题，也发现尚未明确提出的重要共性问题。用苏格拉底式追问分析强prior仍有什么困难、为什么、能否改进。 | 同行能理解问题为何重要、已有解决程度及进一步研究的价值；不因有人研究就避开，不为保住原算法缩题。 |
| **3．设计方法** | 先明确所需能力，再主动寻找本领域与其他领域的成熟机制，必要时改造或自行设计，形成完整技术路线；同步检查贡献是否已被实质覆盖。 | 解释中心机制为何有效、相对已有能力推进在哪里；不是模块拼接，不限于从失效分析产生方法，也不要求算法不可替代。 |
| **4．快速验证** | 用保留关键任务困难的最小可信理论或实验，尽早比较充分调优的简单方法和相关强方法，检验机制及实际收益。 | 结果足以决定下一步；公平计入信息、执行与计算成本。若声称性能更好，却不如合理简单方法，该性能主张就没有成立。 |
| **5．共同迭代问题与方法** | 结合检索、推导和实验，判断应修实现、实验、机制、适用条件还是问题，持续提出更有价值的解释与方案。 | 每轮提高问题的重要性、方法的有效性或证据的可信度；局部结果不越界，累计证据也能推动高层调整，不用“只是局部”无限保护原idea。 |
| **6．收敛贡献与完整证据** | 围绕一条有分量的主贡献，补足相关理论、强对照、机制分析、泛化及必要实物验证，组织论文论证。 | 问题—机制—实质进展—证据相互支撑，经得起最接近工作的比较与替代解释检验；理论条件、失败和适用边界准确。 |

各步交叉循环，不是串行许可关卡。不必先证明所有已有方法失败才设计方法，也不能一直调研、诊断而不提出并实现候选方案。初期允许有依据的假设进入低成本验证，后期补齐贡献证据。仿真保留任务真实必要结构，不靠堆复杂度或制造条件让方法获胜。

从早期同步梳理论文逻辑：具体任务与重要矛盾 → 已有能力与未解困难 → 中心机制 → 实质进展与证据。说不清时返回研究设计，不能靠文字包装补足科学贡献。

## 三、执行原则

- **保持核心问题连续，允许有依据地修订。** B0完整问题和方法是可修订的起点，已有候选不是必须保留的答案。问题与方法随认识共同优化；实质换题需说明依据、影响与可选方向，由用户取舍。题内探索主动推进，不反复求批，不逐渐漂移成抽象、过小或过大的题目。
- **分清本领域强prior与外域迁移机会。** 按问题、条件、机制和实际能力判断，不能只看算法名称或模块重合。本领域已覆盖的贡献应修正判断、更新现状并继续深挖重要困难；外域成熟机制应主动借鉴，检查适用条件与必要改造。部件已有不否定贡献，迁移本身也不证明贡献。
- **依据证据判断，按阶段推进。** 仓库内容和已发表论文均须独立判断；区分原文结论、agent归纳、假设和已验证结果，重要判断可追溯。事实与数学不由预期决定。不确定性只是候选关注点，不是既定选题或固定门槛；不以终稿要求阻断初期探索，也不以初步结果宣布达标。
- **自主推进，简洁记录。** 按需使用文献、工具或skill，每轮说明问题和方法的变化、关键证据与下一决定。长期要求不堆当前实验和历史细节；保留有复现价值的源码、配置和必要结果，包括不利结果。B0快照、检查及自动提交推送遵循[AGENTS](../AGENTS.md)。讨论材料先梳理建议，经用户确认再写为长期约束。
