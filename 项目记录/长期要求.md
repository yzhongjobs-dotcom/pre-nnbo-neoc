# 长期要求与科研判断

## 目标与优先级

用户目标是把既有idea打磨到**顶刊水平**：研究问题、现有方法不足和方法一起迭代，使方法从问题所需能力及科学依据中自然产生；分析失效成因是其中一条路径。B0完整问题和方法是当前打磨起点；后续局部实验没有充分依据撤掉它，也不将B0冻结为不可修订的答案。目标不是保住一组算法名称，也不是仅让程序跑通。

执行顺序为：用户最新明确要求 → 长期科研原则 → 当前有效工作安排 → 历史计划。事实和数学结论依原文、推导、代码和数据判断，不能用指令优先级或文件标题决定真假。

截至2026-10-15，当前任务是精简项目及完成交接；用户尚未启动下一轮科研优化。文件组织不偷偷变成新选题、推导或科研实验。

## 科研workflow

1. 保留现有研究现状调研模块，本轮重点改进找问题与方法设计。调研建立领域整体认识：技术路线、有效机制、解决程度、假设与局限；恢复strongest prior的强版本。重要判断须能回查论文具体内容，区分论文明确结论、AI归纳和待验证猜想。找问题、设计方法时按需要继续调研、更新现状，三者反复迭代。
2. 找问题保留两条路径：领域公认的重要难题，以及尚未被明确提出的共性failure。前者可来自一篇论文，多篇反映共性更有依据；后者从领域应用与第一性原理出发，结合多篇论文检验。主动追问文献冲突、解释缺口和边界条件，采用头脑风暴、质疑和苏格拉底式追问，不只摘录作者局限。问题须符合领域taste，让同行看清任务后果、具体困难及值得推进的认识或能力。已经被研究不等于已充分解决。
3. 提出新问题或实质换题时，列出一个或多个候选，说明具体痛点、文献依据、已有解决程度和研究价值，由用户选择后进入依赖该选择的方法设计。B0完整问题和方法仍是本项目已给定的打磨起点，不借此从零选题；已选问题内的常规细化、调研和方法探索无需逐次请求批准。认知深入可调整问题，但警惕脱离核心科学意图、变得过于抽象或过小/过大；实质改题应说明原因并交由用户选择。
4. 围绕选定问题锚定可调整的技术主线。优先理解、迁移其他领域成熟方法的作用机制，尝试直接复用、必要改造与融合，需要时自行设计，形成适合问题的完整路线。方法设计不限于从失效成因推导机制：RCA → Principle Search → Principle Competition只是一类路径；representation-first、formal-generalization、measurement-first、capability-composition等形成模式后续逐步吸收，不要求先建立完备分类。
5. 贡献检查与验证属于方法设计。紧扣问题、任务条件和已有能力，判断一项工作是本领域强prior还是外域可迁移方法，不只按学科标签判断。本领域强prior若已实质覆盖问题或拟议贡献，更新现状，回到找问题阶段继续追问它及相关方法有哪些重要failure、为什么仍存在；不能靠不断缩题避让。只有模块重合不构成撤退理由。外域成熟方法是迁移机会，应检查机制适配、必要改造及实际贡献；迁移本身不自动等于强创新。
6. 用最小而有判别力的理论或仿真检查重要判断、方法能力及边界；对failure驱动的路线同时查已有方法为何失效、我们是否改变成因。任务条件来自领域，不为了制造算法优势随意添难。持续依据文献挑想法的毛病，不把“前十个想法”或“三轮质疑”等经验变成固定流程。
7. 不利结果先定位受影响层次：实现错修实现，载体遗漏修载体，方法不匹配改方法，问题不准就调整问题。问题与方法可随现状理解和机制证据共同迭代，不必等到问题被严格反证；但每次调整须有对应层次的理由，局部负结果不自动要求缩题。能复用的复用，不能复用的重做。
8. 最终论证：重要问题需要什么能力 → 强方法为什么仍受限 → 方法机制为何由此产生 → 实际推进了什么、边界是什么。

通用控制贡献与超声应用贡献均可审查；不为了躲避一个应用阴性结果转成琐碎数值题，也不强迫通用问题先通过超声指标。

## 通用Harness建设原则与本项目边界

用户对通用科研Harness的建设目标是：先得到能稳定产出顶会顶刊级方法的可运行系统，优先纠正过度防守、混淆领域prior与外域迁移、研究问题漂移、方法形成路径单一；后续逐步完善，不先建设覆盖所有创新模式的完备理论。这是建设与评价目标，不能据此宣称已有系统达到该能力。

Academic Research Suite与Nature Skills是后续可考察借鉴的资源，当前没有启动相关模块改造。上述原则用于指导本项目接手和未来科研，不把R15研究目标替换为Harness开发，也不表示本轮已经启动idea优化。

## 必须避免的已发生failure

| 过去的错误 | 今后如何处理 |
|---|---|
| 看到已有工作就避让，逐个检查模块是否全新 | 还原已有能力、继续追问重要边界；评价整项科学进展 |
| 反复要求“必须NNBO/NEOC” | 检验机制是否自然推进问题，不设特定算法不可替代性门槛 |
| 简化任务中固定/简单控制够好，就缩小整个研究问题 | 先检查载体保留了什么，只更新证据支持的结论 |
| 添加约束、目标或未来分支直到算法赢 | 先证明条件和困难来自领域；容量不足不能靠更新器克服 |
| 人为给定理想刚度，再证明提前信息有用 | 让动作由实际任务和动力学生成，查真实观测如何改变决策 |
| 精确节点根被当作优质策略 | 分开根误差、critic域内质量和实际轨迹性能 |
| 原NNBO复现跑通就认为B0固定根已修复 | 明确状态、动作、目标和学习/求根对象之间的变化 |
| 单次50%跳变、昂贵逐候选检查被当作慢变idea否定 | 对准用户场景；B0逐候选认证与事先适用域直接更新是不同部署设计 |
| 物理慢变被当成小描述符步 | 已知空间状态移动、真实场变化、估计修订分别处理 |
| 所有旧记录都搬入新工作区 | 只保留有明确研究或复用用途的材料；教训压缩，原件用Git回查 |

Q3已撤回为主线；值根只是有条件的机制候选；完整wrench退化核对只是附录已有边界的复核。均不可在后续接手时重命名为新问题或新发现。

## 执行与证据

用户已授权每次完成研究改动后自动提交并推送指定GitHub仓库，无需重复询问。更新[决策记录](研究决策与变更.md)，执行适当检查，再调用 `scripts/research_sync.py`；推送失败保留本地提交并报告、重试，禁止force-push及改写历史。

固定B0快照必须原样保留，工作方法可按证据改变并说明差异。原始数据与结果服务于研究判断和复现；去掉冗余产物不能删掉保留主张所需的唯一证据，也不能只留下有利结果。

沟通用准确简洁的人话。报告具体改动、原因、验证及限制；不要让用户反复阅读库存清单，不堆文档，不将整理量当科研进展。只在需要时阅读相关历史，不把全套检查当成每次工作的门槛。
