# 方法演进审计（2026-11-02 按提交历史核对）

用途：从最终方法出发，逐项看后续实际做了什么、验证到哪一层、失败原因和当时的处理。需要核对时按“证据”列打开原始结果或运行 `git show <提交>`。

**结论分类（用户要求区分）：** ✅ 成立；🧪 只到原型层或实现有缺陷，不能否定路线；❌ 证据到方法层或已有明确机理（仍注明范围）；⚠️ 有收益但未过审查，只是候选。

**阅读提示：**

- **闭环结果**是中位/均值力 RMSE（N），r=失控，L=长失联。
- **开环估计结果**（E1–E4、模量图、窗口估计）是无量纲的 \(|\ln(\hat k/k)|\)；斜杠表示中位/P95 或中位/P90，表内已写明。不要与力 RMSE 混读。
- “每族 50”指诊断集（110000+），除非另有说明。§ 指 [methods 记录](../../research/optimal_impedance_question_and_methods.md)。

## 5. 反复出现的偏差模式

| 模式 | 例子 | 对新工作的要求 |
|---|---|---|
| 诊断出原因后不修原候选，转向下一模块 | E3、E2-A、E4-A、模量图 | 先按诊断结果修这一环，再判断路线 |
| 把原型结论扩大到路线 | “接触模型收益上限小”“C1 导纳不相容”“GLS 不采纳” | 结论写明对象是哪个实现 |
| 用错误的上限 | 用 Wij 代理代替本方法结构下的真值替换 | 上限用同结构真值替换 |
| 先做试验、后贴机制名 | 监督切换、语音增强、E2 递推 | 实验前写出：升级哪个模块、需要什么条件、为什么这个机制满足 |
| 为省事改掉已批准的方案 | §21.5 → 阈值 + 融合 | 偏离方案先说明依据，等用户确认 |
| 不查历史，重复已否定做法 | Kalman 平滑、上调规则 | 动手前查本文件第 0 节和 §19.3 |
| 只测随机噪声就声称传感器稳健 | RM65“结论不变” | 偏置、标定误差、未建模耦合都要进测试 |
| 报告挑统计量或对照 | 中位数对 p90、\(a_f\) 对照选择 | 同时报告中位、均值、失控、长失联和全部对照 |
