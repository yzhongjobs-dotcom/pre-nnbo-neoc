# 长期科研要求

本文件是本项目的统一科研要求，2026-11-09 按用户梳理的逻辑重组。第一至第四节各小节开头的正文是用户原话；“细则”来自此前已确认的长期要求，保留其实质内容。具体论文依据见[逐例逆向分析](../research/independent_reverse_analysis_of_top_journal_methods.md)，当前任务见[HANDOFF](HANDOFF.md)，科研偏差与教训见[失败复盘](research_failures_and_corrections.md)，版本历史由 Git 保存。

**总逻辑：** 从真实研究问题出发 → 理解具体场景 → 挖掘物理与数学洞见 → 形成有依据的理论和 Method → 推导预期 → 实验验证与迭代 → 形成顶刊级完整工作。

## 一、研究目标：究竟要解决什么问题？

在动态、空间非均匀的接触环境下，实现机器人可靠、稳定、高精度的接触力控制。

典型任务是机器人自主超声扫描胸腹部：探头沿既定轨迹从软组织移动到肋骨区域，再离开肋骨，同时存在呼吸、偶发身体运动、接触噪声以及机器人伺服延迟。

核心困难是：接触力变化可能来自组织运动，也可能来自接触刚度变化，二者相互混淆，而控制器需要根据这些信息及时采取不同的控制动作。

因此，研究最终要实现的是：在有限接触观测下，可靠获取控制真正需要的接触信息，并将其用于运动补偿与控制调整，实现动态、非均匀环境中的高性能恒力控制。

**细则：**
- 目标是持续产出有实质科学贡献、证据足以参与顶刊竞争的论文，本项目是当前这一篇。问题应具体重要，方法应专业完整、适合当前问题，并取得相对领域充分已有能力的实质进展；证据支持所声称的能力，条件、成本与边界准确。
- k、d 分离是其中一个重要问题，但完整 Method 还涉及信息获取、预测和控制。d 是由所选观测模型定义的剩余项，不能未经分析就把它等同于人体运动。
- 保持核心问题连续，允许有依据地修订。B0 完整问题和方法是可修订起点，已有候选不是必须保留的答案。问题与方法共同优化；实质换题说明依据、影响与可选方向，由用户取舍。题内探索主动推进，不反复求批，不逐渐漂移成抽象、过小或过大的题目。

## 二、研究者应具备什么能力与思维方式？

要求以顶尖数学家和机器人科研学者的水平开展研究。以陶哲轩式的数学研究思维为参照，其核心不是套用某个算法，而是：具备广阔的数学视野、深刻的物理直觉、严密的理论推导能力和灵活的问题解决能力。

面对研究问题，应当能够：

- **发现隐藏条件。** 不仅使用显式已知的信息，还要从物理机制、任务几何、时间与空间规律、观测过程等方面，发现尚未充分利用的隐含条件，并判断其成立范围。
- **抓住本质。** 从复杂现象中提炼真正的数学问题，例如可辨识性、偏差—方差权衡、变化检测、动态预测与闭环稳定性，而不是停留在算法表面。
- **灵活使用数学工具。** 熟悉本领域及其他领域的经典和前沿理论，例如贝叶斯推断、系统辨识、鲁棒统计、变点检测、最优化、状态估计和控制理论。需要什么就研究什么，能借鉴成熟理论就借鉴，需要新的数学构造就自行推导。
- **坚持严密性。** 充分说明假设、推导、成立条件、理论预期与适用边界。不能把直觉、近似、经验公式或尚未验证的猜想直接当作理论结论。

重要的是：数学能力服务于解决真实研究问题，而不是为了让 Method 显得复杂。

**细则：**
- 隐含条件需要从真实物理机制中发现，通过理论分析、文献和实验判断其成立条件，不能未经核实就直接假定成立。区分原文、agent 归纳、假设和实测，重要判断可追溯，事实与数学不由预期决定。
- 从现象提炼结构。用量纲、尺度、对称性、守恒关系或保留关键困难的简化极限，判断哪些作用主导、哪些量可以消去、哪些信息仍藏在观测里。必要时改变变量、表示或估计目标，让原本混在一起的机制显露出来，再检查这一洞见在真实工况下能走多远。

## 三、完整的研究流程

以下步骤是研究思维的逻辑顺序，而非必须完成一步才能进入下一步的僵硬流程。文献、理论、方法和实验可以相互促进、反复迭代；但每次迭代都应使问题认识或方案质量实质性提高。

### 1. 从研究问题和真实场景出发

首先明确要解决什么问题、现有方法已经能解决什么、还有哪些重要困难。

选择少量有代表性的场景，研究其真实物理过程。例如跨肋骨时，探头的方向、速度、接触区域、呼吸运动、刚度变化曲线分别是什么样，以及它们相互作用后产生什么现象。

通过高水平文献、真实数据和物理分析建立依据，不为了验证某个候选方法而人为构造有利场景。

**细则：**
- 不需要覆盖所有场景，更不需要将所有场景叠加。
- 围绕核心问题核读原文，理解强方法的机制、充分能力、条件与代价。最接近的工作要找全，检索不再出现新的直接近邻为止；外域相近机制只记录作方法参考，不写进现状。
- 从实际需求、目标冲突、已有能力边界和第一性原理深入追问。既研究公认难题，也寻找尚未清楚提出的重要问题。不因强工作存在退避，不为某算法能赢而缩题。
- 仿真可按任务物理需要调整，也可能无需调整；须说明依据、适用于各方法并保持公平，不能为候选获胜制造条件。仿真保留任务真实必要结构，不靠堆复杂度让方法获胜。

### 2. 从具体场景中发现核心数学与物理洞见

分析已知量、未知量、显式和隐含条件、物理约束、信息结构以及现有方法的关键假设。

例如：刚度在空间上可能连续，但局部变化速度会迅速改变；呼吸运动具有一定结构；相邻滑动窗口共享大量数据，其误差并不独立。

进一步追问：这些信息能否帮助我们区分真实刚度变化与观测噪声？需要哪些条件？什么时候不可辨识？

这一阶段的成果应是能够指导方法设计的核心洞见，而不只是描述一个 failure。

### 3. 利用数学理论形成解决思路

从洞见出发，寻找最适合的数学表示、假设和求解机制。

广泛研究已有成熟方法，分析它们解决问题的机理、成立条件及局限。可以继承、改造、自然组合，也可以自行设计。

对候选机制进行完整理论推导，明确为什么预计能够解决问题，相比已有方法多获得了什么能力，以及这种优势在哪些条件下成立。

先建立理论依据和预期，再开展针对性实验；不预先指定 Kalman、MHE、神经网络或其他算法为最终答案。

**细则：**
- 两种常见设计思路均应积极使用，可交叉，不是穷尽分类：沿成熟方法主线改进，调整关键表示、模型、假设、信息、训练、优化或执行结构；围绕明确问题自然组合、改造方法，各部分应有具体任务作用和协调关系，不能用模块清单代替设计。
- 先定位最强方法卡在哪个环节（表示、模型、信息、优化/训练、执行），改动对应瓶颈。按共同的数学障碍在本领域及外领域找成熟机制，核对其成立条件与本任务可用信息、物理约束和实时要求，适合就迁移并重新推导。现成机制不适配时，从支配关系和约束出发自行构造。
- AI 应主动形成和推导候选，再用最相关的强工作、反例和数据检验其关键假设。某条推导失败时，判断其中的结构洞见是否仍成立，据此修正论证、改换表示或探索机制实质不同的路线。具体做法见[方法设计](research_workflow/03_method.md)。
- 参考顶会顶刊方法时，先判断其解决的真实问题是否也存在于本项目，再决定借鉴哪些机制、如何改进。不预设新模型一定更好，也不因初步实验不理想过早放弃。
- 深入强工作，主动寻找迁移机会。本域实质覆盖时修正贡献判断并继续深挖，不因算法名称或模块重合退避、缩题。
- 借鉴正常，改进可以小。关注借鉴后具体做了什么、是否适合当前问题、连接是否专业、结果是否有效，以及相对最接近工作的实际进展。不因方法已有或改动不大否定价值，也不因做了迁移或拼合就认定创新成立。
- 改造保留关键机制、明确适配推导，不能以简化替身的成败评价完整原方法。正向机制启发同样是正常来源，不限于失败分析驱动；改进空间不限于已被证实的缺陷。不能一直调研、诊断而不提出并实现候选方案，诊断性调参或开关不能替代方法研究。

### 4. 逐步形成专业、完整、协调的 Method

明确各组成部分需要解决什么、输入输出是什么、为什么采用这种机制，以及信息如何在模块之间传递。

既要深入优化当前模块，也要保持整体视野。如果某个局部洞见影响其他模块，例如刚度辨识中的呼吸模型与后续运动预测存在共用信息，就应重新审视整体设计。

不要求每个模块都有创新，也不预设原架构必须保留。最终应形成自然统一、专业完整、具有实质创新的解决方案，而不是算法堆砌。

**细则：**
- 即使沿用原有模块，也要有充分理由说明为什么采用它，而不是已有文献中的其他成熟方法。
- 整体先行，部件按需审视。先审视整体能力、困难与瓶颈，再问各组成部分为何需要、设计是否合适、有哪些更好已有机制、应保留/改进/替换/删除什么。激励、干扰/接触表示及估计对象/求解可单独或联合改造，其信息与控制接口必须协调。不把“逐个检查”执行成“逐个找升级”。
- 如果无法一次完成，可以先规划清楚完整 Method 的各个部分，再从第一个模块开始深入优化。
- 如果研究过程中发现需要实质性改变整体 Method 的模块划分或技术路线，应先停下来与用户讨论。

### 5. 由理论预期驱动实验，并根据证据迭代

先推导理论上应该观察到什么，再设计少量具有区分能力的代表性实验。

例如，理论预期某方法在平稳时降低方差、在变化时减少滞后，就应分别检验平稳噪声、上升、峰顶反转、下降及异常扰动，而不是只看一个总体平均误差。

如果实验与理论不符，必须回到原始数据，从理论假设、模型、实现、实验条件和指标定义等方面寻找根因，再据此修正候选。

不能为了得到预期结果而调参或修改仿真，也不能在失败原因尚未查清时直接换一个算法。

**细则：**
- 用保留关键任务困难的最小可信理论或实验，尽早比较充分调优的简单方法（用于诊断，不作主基线）及相关强方法。若声称性能更好却不如合理简单方法，该性能主张尚未成立；不以一次简化实验裁决整套构想。
- 结合原文、推导和结果，判断应修实现、实验、机制、适用条件还是问题。局部结果不越界，累计证据也能推动高层修订，不用“只是局部”无限保护 idea。
- 分开判断错误、方法成效和证据范围。区分基线、候选改动和被测实例，核清理论对象、数值近似、实际闭环及部署成本。不确定性是候选关注点，不自动成为新题或永久门槛。
- 方法设计是主目标，对照实验服务于形成与改进方法。多候选分别设计、分别实验和判断；不能把补齐比较方法当作研究完成，也不能以融合或挑选局部结果代替各候选的实际证据。

### 6. 完成闭环验证，收敛到顶刊级贡献

局部模块表现好，不代表完整控制系统一定更好。因此，关键候选需要及时接受闭环验证。

与最相关的成熟方法进行公平比较，既看估计精度，也看力误差、冲击、失联、稳定性、计算成本以及适用边界。

最后将真实取得的改进组织成清楚的研究主线：重要问题是什么、已有方法为什么存在不足、我们发现了什么关键机制、如何解决，以及证据如何支持新增能力。

**细则：**
- 验证随研究需要进行，不固定成“模块研究全部完成后才做闭环”。此前已经出现过刚度估计改善却导致闭环控制恶化的情况。
- 实验从本研究问题和候选方法出发。先明确各候选要验证的能力，再选择适合任务的比较算法，核准复现或任务适配后公平比较；没有合适对象则无需强行设置基线，也不因没有外部基线便声称方法已达顶刊水平。不能先选一个方法或照搬论文任务，再让候选迎合它。
- 正面对比最像自己的方法并讲清机理区别；指标用任务物理指标，不用方法自身代价。固定阻抗取方法自身上下界两端。
- 贡献要经得起强方法比较与替代解释检验，理论和实验各支持对应主张。方法构造、原型收益和最终论文竞争力分开判断。
- 将实际改进组织到恰当的能力层次，问题、方法、贡献从早期同步梳理，随结果修订。呈现中说不清的地方，应反馈到设计和验证。不将小改造夸成全新范式，也不因只列模块或公式而低估实际贡献。
- 成稿可以把方法写得像从问题自然推导出来；逆向分析还应拆出成熟基础、具体调整、适配关系和验证作用。不能仅凭公开成稿声称恢复了作者真实的发现顺序，也不能把会解释论文等同于会形成方法。

## 四、要求与验收标准

### 1. Work 第一，Method 和 Story 同样重要

最终目标是具备 T-RO/IJRR 竞争力的完整研究。必须真正解决重要问题，具有实质的技术改进和可靠的任务性能。与此同时，方法要专业、自然、有创新，研究问题与贡献的组织要准确、有说服力。三者缺一不可，但不能以包装替代实际效果。

**细则：** 从具体顶会/顶刊论文理解方法和贡献，再用于本项目判断。样本中的实际设计提供参照，不构成统一录用清单；不设固定提升比例、全新组件数量、独有算法、庞大改动或定理数量要求。论文发表身份、流程完成和局部胜率均不能单独证明达标。具体参照见[逐例分析 §2–4](../research/independent_reverse_analysis_of_top_journal_methods.md)：R01 的共同相位小扩展、R13 的受约束表示、R12 的目标动力学分工、R11 的正向迁移、R19 的简洁残差结构、R21 的物理—可执行集合。例子用于理解尺度，不规定本项目的必选形式。

### 2. 理论与实验必须相互印证

每个重要改进都应具有明确的数学或物理依据、可检验的预期与对应实验。理论优越性不能直接等同于实际优越性。实验不符时必须找根因，而不是选择性汇报或者为了结果修改假设。

### 3. 方法设计以解决问题为中心

不强制采用新算法，不强制增加模块，也不强制保持现有结构。既不因数学方法经典、简单而轻易否定，也不因方法复杂、使用前沿技术而认定其具有顶刊创新性。判断标准是它能否带来相对于最接近工作的真实、重要的新能力。

### 4. 研究应当充分、严谨，但避免无意义的工作量

文献核查要深入，仿真要物理可信，基线比较要公平。实验从少量代表性任务开始，针对具体问题扩展，不默认全组合、大量随机种子或重复计算。优先复用正确的已有代码和数据；Claude 与 Codex 可以灵活分工，但以科研质量为优先。

**细则：**
- 仿真以科学问题和证据链组织。每个场景回答明确科学问题，每组比较针对关键替代解释；不靠更多任务、随机种子或篇幅体现深度。不默认全面参数扫描、分布外条件或任务×方法全组合。同一任务一般重复 3–5 次，工况只保留回答问题所需；既有 2–4 场景作为组织参考，不变成配额。
- 若涉及低概率失效，须给相应证据或限制结论，不能以少量成功声称尾部安全。
- 少量强相关对照、必要机制消融、物理任务指标和计算代价为主。诊断迭代记录不直接铺成论文实验章节。有候选就如实报告正负结果，不确定时核对同类顶刊原文。
- 把深入推导和计算用在可能改变方法选择、适用条件或研究判断的地方。优先做能区分竞争解释的关键推导、反例或小实验。当前路线反复遇到同一障碍时，依据该障碍决定改换表示、补充可信信息，或保留已有结论并说明还缺什么证据。

## 五、执行与汇报

- **自主推进，简洁记录。** 按需使用文献与工具，每轮说明问题和方法的变化、关键证据及下一决定。关键决定及理由（含被否方案、推翻条件）简记于[决策记录](decision_log.md)，外部 agent（Codex、ARIS）的任务书与输出原文存于 [agent_runs](agent_runs/)，仅供复盘，不喧宾夺主。长期要求保留稳定认识，具体论文、实验和失败细节放在相应文件。保留可复现源码、配置和必要正负结果。B0 保全、检查及自动提交推送遵循 [AGENTS](../AGENTS.md)。
- **长期约束的修改。** 新讨论先梳理建议，经用户确认再写入长期约束；已确认要求不反复请求批准。
- **汇报直接给结果。** 在对话中直接给出具体数字、表格与结论，并说明所提方法相对基线如何、为什么；不只给文件链接。大规模运行前先说明额度消耗。
- **汇报说清理解、工作与结果。** 用几句话具体说明如何理解研究问题及候选、实际改了和测了什么、结果是什么。提到比较须说明对象和为什么比较，给必要数字、范围和未完成内容；不只报“补了 24 组”，也不用抽象计划代替实际工作。
