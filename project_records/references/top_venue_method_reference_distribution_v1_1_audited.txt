======================================================================
0. 这份文件要教给 Codex 的不是“规则”，而是“真实顶刊长什么样”
======================================================================

本文件不是抽象 checklist，也不是“满足若干条即可判定顶刊”的机械 Gate。
它的目标是把研究者对顶会顶刊 Method 的经验感觉转化为：

Reference Corpus（真实参考样本）
→ Unified Paper Portrait（统一论文画像）
→ Pairwise Comparison（成对比较）
→ Venue Profile / Reference Distribution（发表画像 / 参考分布）
→ Current-Method Distance（当前技术路线与真实顶会顶刊的差距）

以后真正要问的不是：
“当前 Method 有没有某个模块？”
“用了几个新算法？”
“公式够不够多？”

而是：
如果把当前 Method 匿名放进一批真实、近领域的 T-RO / IJRR / ICRA / RSS 论文中，
它的问题规模、真实科学增量、贡献包装、方法复杂度、理论深度、工程闭环和证据强度，
是否处于同一专业分布？如果不像，具体哪里不像？

---------------------------------------------------------------------
0.1 经验标签
---------------------------------------------------------------------

[S] Stable Pattern（稳定规律）
    在多个 venue、多个不同形态样本中反复出现，可作为高置信经验规律。

[V] Venue Tendency（venue 倾向）
    在当前样本中对某 venue 较稳定，但不是必要条件或充分条件。

[E] Example-Specific（个例）
    只说明某篇已发表论文这样做也被接受，不能泛化为硬标准。

[R] Red Line（红线）
    会让创新性、复杂度或 venue 判断系统性失真的做法。

重要：
“样本里常见” ≠ “必须”
“样本里没出现” ≠ “不能”
“某篇顶刊很复杂” ≠ “顶刊必须复杂”
“某篇顶刊很简单” ≠ “简单就一定够顶刊”


---------------------------------------------------------------------
0.2 本标尺能判什么、不能判什么（反向审计后新增）
---------------------------------------------------------------------

本标尺的目标是判断：
“当前 Method 是否处于真实近领域顶会顶刊的经验分布内，以及与目标 venue 的代表论文相比差在哪里。”

它不是期刊录用概率预测器，也不能把实际发表 venue 当作绝对 ground truth。
原因：不同 venue 的质量分布存在重叠，作者投稿策略、篇幅、审稿历史、时间窗口也会影响最终发表地点。

因此最终结论必须写成：
- Method-level alignment（方法层面对齐程度）；
- nearest published exemplars（最接近的真实发表样本）；
- below/above-distribution dimensions（低于/高于参考分布的维度）；
- target-venue readiness（目标 venue 就绪度）；
而不是“该论文一定会被某 venue 接收”。

[S] 顶会顶刊标准是 empirical alignment（经验对齐），不是 deterministic venue classifier（确定性 venue 分类器）。
[R] 不得用“某篇类似论文实际发在 RAS/TIM/RA-L，所以当前 Method 一定不够 T-RO”或反向推理代替 Method 审计。

1. Field Boundary 与 Reference Corpus
======================================================================

1.1 主领域边界

连续物理接触 / 软接触机器人操作
+ 力调节与阻抗 / 柔顺控制
+ 在线或预测式阻抗选择
+ 接触 / 环境 / 模型不确定性
+ 医疗接触 / 机器人超声作为关键应用子域

不以 UAV、位姿图优化、纯腿足 locomotion、通用数值优化等远领域论文定义本领域 venue 门槛。
远领域论文只可在 strongest prior 或跨领域机制迁移时使用。

1.4 Paired Boundary Calibration Corpus（同研究线升级对照；反向审计后新增）

仅看一组“已发表顶刊”不足以学习 venue 边界。必须优先使用同一研究线、相近作者/问题的前后版本，观察从 conference / specialized journal 到 T-RO/IJRR 时真实增加了什么。

P1. Angelini et al., IROS 2019
    Online Optimal Impedance Planning for Legged Robots
    → Pollayil et al., T-RO 2023
    Choosing Stiffness and Damping for Optimal Impedance Planning
    重点：从较窄/结构受限的在线阻抗规划，扩展到更一般 inertia 条件、解析/数值统一处理、更完整数学与多机器人证据。

P2. Wijayarathne et al. conference version
    → Wijayarathne et al., T-RO 2023
    重点：2-block → 3-block decomposition、online MPC、dynamic disturbance experiments、low-level execution controller。
    该 pair 直接证明 journal upgrade 不必“推倒重来”，可以是 generality + online execution + evidence closure 的系统增强。

P3. Fu et al., TIM 2024
    Optimization-Based Variable Impedance Control of Robotic Manipulator for Medical Contact Tasks
    → Fu et al., T-RO 2025
    Human-Inspired Active Compliant and Passive Shared Control Framework...
    重点：从 online QP stiffness + energy tank + medical-contact experiments，扩大到 shared control + whole-system passivity + operator-workload/system evidence。

P4. Jin et al., ICRA 2022
    Constrained Variable Impedance Control Using Quadratic Programming
    → Jin et al., T-Mech 2023
    Model Predictive Variable Impedance Control...
    重点：focused constrained update → multistep predictive formulation / broader precision-compliance tradeoff。

[S] paired comparison 比跨作者、跨问题的 venue 猜测更适合学习“升级到更高层级时真实多了什么”。
[V] journal upgrade 常见于 generality、mathematical closure、online execution、evidence breadth 或 claim scope 的扩大；不是简单增加算法数量。

======================================================================
2. 每篇论文必须按同一套 8 维画像读取
======================================================================

D1 Problem Level（问题层级）
- 真正 failure / bottleneck 是什么？
- 是基础理论、一般控制、系统问题还是窄应用问题？
- 如果不解决，机器人具体缺失什么能力？

D2 Scientific Delta（真实科学增量）
- strongest prior 已做到哪里？
- 本文实际多走了哪一步？
- 新意是在建模关系、决策变量、反馈角色、算法结构、理论边界、实时能力还是系统能力？

D3 Contribution Packaging（论文级贡献包装）
- 作者把真实增量包装成什么科学对象？
- 是 new relation、generalization、unified framework、capability leap 还是 system-level interconnection？
- 哪些成熟工具没有被包装成独立创新点？

D4 Method Complexity（方法复杂度）
- 主科学机制几层？支撑机制几层？
- 建模、优化/学习、稳定/安全、实时执行分别承担什么角色？

D5 Necessity / Structural Naturalness（必要性 / 结构自然性）
- 每个 major module 是否对应真实 failure？
- 是否有明显更简单替代？
- 作者是否在能用简单方案时主动用简单方案？

D6 Theory / Mathematical Closure（理论 / 数学闭环）
- 稳定性、无源性、收敛、物理一致性、约束、鲁棒性做到什么程度？
- 理论深度是否与 claim 对齐？

D7 Engineering Closure（工程闭环）
- optimizer / planner 输出是否真实进入 controller？
- 是否 online / real-time？
- 是否处理执行接口、传感、模型误差、接触失效等实际问题？

D8 Evidence Closure（证据闭环）
- baseline 是否直接打到 paper-level claim？
- 是否有 ablation / disturbance / dynamic environment / hardware / user study？
- 证据强度是否与 claim 和复杂度匹配？

[S] 最终判断必须基于八维整体画像，不能由单一维度替代。

---------------------------------------------------------------------
2.1 每篇论文必须做“双重贡献重建”（反向审计后新增）
---------------------------------------------------------------------

不能直接把作者 Introduction / Contribution List 当成 Scientific Delta。
每篇论文必须同时记录：

A. Author-Stated Contribution（作者自述贡献）
B. Auditor-Reconstructed Delta（审计者根据 strongest prior 独立恢复的真实增量）
C. Packaging Uplift（作者如何把 B 提升到 mechanism / relation / capability / framework 粒度）
D. Packaging Validity（该提升是否被公式和实验真正支持）

如果 A 很强而 B 很小，应标记 narrative inflation risk；
如果 B 合理但 A 只是模块列表，应标记 under-packaging；
如果 A 与 B 基本一致，说明 packaging 与真实增量匹配。

[R] 不得以作者自己写的“novel / first / contribution”直接证明 novelty。

---------------------------------------------------------------------
2.2 Complexity Vector（复杂度向量；反向审计后新增）
---------------------------------------------------------------------

“低/中/高复杂度”只能作为摘要，正式 pairwise comparison 还要拆成：

C = [
  C_model      : 接触/环境/机器人模型层数与耦合程度,
  C_decision   : 在线决策变量与决策层级,
  C_solver     : optimizer / decomposition / inner-outer solver 层级,
  C_guarantee  : robustness / passivity / safety / certification 层级,
  C_execution  : high-level / low-level / estimator / asynchronous execution loops,
  C_evidence   : 为证明这些复杂度必要而需要的 ablation / hardware / user evidence burden
]

不设置固定数值阈值；只做同 problem/delta/claim 下的相对比较。

[S] 过度设计的核心不是“模块多”，而是某个 complexity axis 显著高于相似 Scientific Delta 的真实论文，却没有对应更强 capability / guarantee / evidence。

3. T-RO 真实论文画像
======================================================================

3.1 Wijayarathne et al., T-RO 2023

Problem：
已有 TO 可发现接触、利用接触力帮助规划，但软接触环境下准确 simultaneous motion + force tracking 仍不足；
full robot + deformable contact constrained TO 又难以在线求解。

Scientific Delta：
核心不是 Hertz、DDP、ADMM、IK、MPC 任一工具本身，而是：

deformable contact physics
→ constrained trajectory optimization
→ desired motion and force jointly planned
→ distributed solution enables real-time MPC

相对作者自己的 conference version，journal 扩展并不“翻天覆地”：
- 2-block → 3-block，独立抽出 IK；
- planner 在线 MPC；
- 更强 static/dynamic disturbance 实验；
- 增加 low-level admittance controller。

Packaging：
“soft-contact dynamics + constrained force-motion TO + real-time MPC validation”，而不是“发明 DDP/ADMM/IK”。

Complexity：中高。
contact model + robot/contact dynamics + DDP/IK/projection + ADMM + MPC + low-level force controller。

Necessity：
问题本身包含 dynamics、kinematics、constraints、online solve，因此分解结构有明确作用；低层 admittance 是 execution support，不是第二条 Scientific Delta。

Theory：
重点在 contact dynamics + constrained optimization 闭合，不是大型新稳定理论。

Engineering：
real-time MPC + 高层规划 + 低层控制 + static/dynamic disturbance。

Evidence：
模型验证 + 多 Cartesian motion + force-motion tracking + disturbances。

经验：
[S] 大量成熟工具可同时出现在顶刊，只要共同服务一个新的 paper-level relation。
[S] 复杂求解结构必须由问题规模解释。
[E] DDP–IK–Projection + ADMM 只是本文特定实现，不是 T-RO 标配。

3.2 Pollayil et al., T-RO 2023

Problem：
阻抗控制研究很多，但“应该在线选什么 stiffness/damping”缺少一般、实时、无需额外 F/T sensor 的方法。

Scientific Delta：
给定 Cartesian inertia 在线规划 stiffness/damping，使 perturbation effect 受限；
对 diagonal-dominant inertia 给出解析路径，对更一般 non-diagonal case 用数值优化，形成更一般 impedance planning framework。

Packaging：
不是“optimization + impedance control”，而是“online impedance planning itself as a control-design problem”。

Complexity：低到中。
一个明确 optimization core + analytic/numerical branch + stability/passivity + online loop。

Necessity：
能解析就解析，只有一般 case 才数值求解。
这直接说明顶刊不奖励“能复杂就复杂”。

Theory：
optimization formulation、performance bounds、stability/passivity。

Engineering：
无需 F/T sensor；quadruped + robot arm；可实时使用。

Evidence：
多机器人验证 generality 和 real-time employability。

经验：
[S] 一个 meaningful generalization + 完整数学/实机即可成立 T-RO。
[S] minimum sufficient complexity 比算法层数重要。

3.3 Li et al., T-RO 2025

Problem：
classical adaptive 对 nonlinear/dynamic environment 和 estimation error 受限；
human-like impedance learning workload 高；RL/DRL 又有安全交互、interpretability、convergence、overfitting 问题。

Scientific Delta：
DRL feedforward learns impedance tuning
+ variable-impedance feedback closes force tracking
+ couch contact model bounds safe sim-to-real transfer
+ stability/convergence analysis + state-aware regression address RL weaknesses。

Packaging：
paper-level capability 是“uncertain nonlinear environment 下，可解释、可安全迁移、具有理论闭环的 learned variable-impedance force tracking”。

Complexity：中等。
learning + VIC feedback + simplified contact model + stability/convergence analysis。

Necessity：
每个 major component 都映射到作者明确指出的一类 failure。

Theory：
Lyapunov / contraction mapping 等直接服务 stability / convergence claim。

Engineering：
sim-to-real；真实机器人；static / quasistatic / dynamic environments。

Evidence：
constant impedance、classical adaptive、proposed method；还比较 regression vectors 支撑 overfitting claim。

经验：
[S] 多组件不等于 overdesign；若每个组件关闭同一 paper-level capability 的必要 failure，可成立。
[S] 方法越多，越需要模块级 evidence / ablation 对应各自 claim。

3.4 Fu et al., T-RO 2025

Problem：
teleoperated medical contact-rich tasks 同时面对 force tracking/safe compliance、operator workload、whole-system passivity。

Scientific Delta：
QP、VIC、shared control、energy tank 均有先例；paper-level delta 是把：
active compliant force regulation
+ human–robot shared control
+ global passivity
组织成完整 medical-contact shared-control framework。

Packaging：
作者承认并引用已有 passivity / energy-tank / shared-control；创新来自 system-level interconnection + 综合能力。

Complexity：高。
leader/follower + bilateral teleoperation + Cartesian impedance + online QP stiffness + force compensation + global tank + shared control。

Necessity：
因为 paper claim 本身同时包含 force regulation、operator assistance、whole-system passivity，所以复杂度与 claim 规模匹配。

Theory：
passivity / energy formulation 服务 whole-system claim；QP 服务 stiffness selection / force performance。

Engineering：
ROS + haptic + robot + real-time QP/passivity。communication delay 未被完整考虑，这是边界，不能自动脑补。

Evidence：
autonomous force tracking + shared-control validation + 12-user usability study；force error / passivity / workload 均有对应 evidence。

经验：
[S] system claim 变大，系统复杂度与 evidence 可合理同步扩大。
[S] system-level contribution 必须用 system-level evidence 防守。
[E] 12-user study 是因为本文有人因 claim，不是一般 T-RO 必需。

4. IJRR 真实论文画像
======================================================================

4.1 Haddadin & Shahriari — Unified Force-Impedance Control, IJRR 2024

Problem：
机器人需要同时具有 compliance 与 exact force regulation，且真实系统包含 rigid/flexible joints、direct/estimated force、contact/non-contact 切换。

Scientific Delta：
不是“force + impedance 第一次组合”；IJRR 版本把既有 UFIC lineage 扩展成更完整的一般理论框架，覆盖更广 robot/system conditions 与 arbitrary passive environments。

Packaging：
“Unified framework”本身就是 paper-level scientific object；贡献强度来自一般性、理论统一性、practical system coverage。

Complexity：高但统一，force regulation、impedance behavior、energy tank、contact transitions 围绕同一 passivity framework。

Necessity：
非常关键：在 contact-loss 问题上，作者指出理论上可继续全用 energy-domain/tank 处理，但会复杂且不实用，因此采用更直接的 state-based shaping。

Theory：高，passivity/stability 是核心贡献本身。
Engineering：覆盖 rigid/flexible robots、sensed/estimated force。
Evidence：多机器人场景支撑 broad framework。

经验：
[S] IJRR 的复杂框架通常需要一般性 / 理论统一性匹配复杂度。
[S] 即使统一理论论文也会主动避免不实用的过度统一。

4.2 Lachner, Nah, Hogan — Physically Consistent Stiffness, IJRR 2025/2026

Problem：
传统 task-space → joint-space stiffness 在 curved configuration space 忽略 basis-vector change，导致 stiffness asymmetry，进而破坏 physical consistency / passivity / energy properties。

Scientific Delta：
change of basis on curved space
→ conventional derivative misses connection term
→ incorporate Christoffel symbols
→ recover physically consistent symmetric stiffness。

Packaging：
不是“加一个 correction term”，而是“修复长期存在的 stiffness physical inconsistency”。

Complexity：低。几乎整篇围绕一个 foundational correction。

Necessity：
无需 MPC、learning、robust stack，因为 problem 本身是基础数学/物理一致性问题；额外模块反而会稀释主贡献。

Theory：深，直接触及 symmetry / energy / passivity。
Engineering：真实机器人验证。
Evidence：验证 correction 的物理后果，而不是大规模 benchmark。

经验：
[S] 顶刊深度与 Method 复杂度没有单调关系。
[S] 基础性数学修正可以用极简 Method 达到 IJRR。

4.3 Piedra, Jeffrey, Khatib — Explicit Force-Based Control, IJRR 2026

Problem：
robotic ultrasound 常用 implicit force/admittance control，force regulation 经过 motion loop，出现动态 bandwidth/phase-lag 瓶颈。

Scientific Delta：
explicit force control 本身不是新发明；真实 delta 是：
identify motion-loop bottleneck in robotic ultrasound
→ directly regulate force/moment at end effector
→ integrate probe orientation / haptic framework
→ obtain much more responsive dynamic-contact behavior。

Packaging：
“explicit force-based architecture is the right control role for compliant robotic ultrasound”，而不是“发明 force control”。

Complexity：中等。
explicit force/moment + 6-DoF haptic + force-based probe orientation + acoustic-coupling alignment。

Necessity：
root cause 若来自 implicit motion loop，则先改 control architecture 就能解决，不需要默认上大型 robust MPC stack。

Theory：重在 force-control formulation / system integration / physical response。
Engineering：dynamic phantom、external perturbation、heterogeneous contact、真实 ultrasound imaging。
Evidence：
对 state-of-the-art integral adaptive admittance：phase lag 121° → 5.76°；平均 force error 约降低 77.7% / 72.6%；还有 image-quality evidence。

经验：
[S] 简单直接的 mechanism change 若精准击中 bottleneck 并产生明显 capability/performance leap，可支撑 IJRR。
[S] 更复杂 predictive architecture 不是默认更高级。
[E] 具体改善数值是个例，不是 IJRR 阈值。

4.4 Xue et al. — Implicit Motor Adaptation, IJRR 2026

Problem：
contact-rich manipulation 的 uncertain physical parameters 让 generalization 困难；domain randomization 可能保守；explicit adaptation 往往需精准 parameter ID 或 retraining。

Scientific Delta：
rough parameter distribution
→ tensor-train implicit policy representation
→ efficient parameter-conditioned policy retrieval
→ avoid precise identification/retraining while retaining adaptation。

Packaging：
“implicit motor adaptation”是一个清晰、命名明确、与 prior 可直接比较的机制。

Complexity：中等；tensor-train representation + policy retrieval + theory，而非多个独立 controller 堆叠。

Necessity：
tensor-train 必须由 efficient parameter-conditioned retrieval 的结构需求解释。

Theory：有 theoretical analysis。
Engineering：多 contact-rich primitives，simulation + real-world。
Evidence：跨多 physical-parameter instances 验证 robust policy/generalization。

经验：
[S] IJRR 也接受“一个核心新算法对象 + 理论 + 广泛 contact-rich 实证”。

5. Top Conference 真实论文画像
======================================================================

5.1 Jin et al., ICRA 2022

Problem：fixed impedance 难以在 precision/compliance 或 task constraints 改变时适配。
Delta：把 variable impedance update 形式化为 constrained QP，在线求可执行参数。
Packaging：“constrained variable impedance via QP”是集中技术增量。
Complexity：低到中，VIC + QP + constraints。
Theory：会议篇幅下完成必要 formulation/constraints，而非大型统一理论。
Engineering/Evidence：在线实现 + 实验比较。

[V] ICRA 可接受非常清楚、聚焦的 technical delta，只要 problem–method–experiment 闭合。

5.2 Beber et al., ICRA 2024

Problem：robotic ultrasound 要安全准确控制 probe–body interaction，同时 tissue mechanics 变化且会 contact loss。

Delta：
online tissue viscoelastic estimation
→ physical constraints for QP variable impedance
→ energy tank / passivity
→ safe ultrasound force control。

Packaging：不是“QP + energy tank”，而是“tissue mechanics informs safe variable impedance in ultrasound”。

Complexity：中等，tissue model/estimation + QP impedance + physical constraints + tank/passivity。
Necessity：每层都能映射到 target-task failure。
Engineering：real-time + patient dummy torso + contact loss。
Evidence：安全、force control、contact-loss behavior 与 claim 对应。

[S] conference 也可以有完整多模块链，不能以模块数区分 conference / journal。

5.3 Reuss et al., RSS 2022

Problem：rigid-body dynamics 可建模，但 stick-slip friction、flexibility 等 history-dependent/partially observable effects 难捕捉；高 feedback gain 又降低 compliance。

Delta：
physically consistent rigid-body prior
+ recurrent neural residual
→ better inverse dynamics feedforward
→ same tracking with much lower impedance feedback gains。

Packaging：不是“physics + RNN 组合”，而是“hybrid inverse dynamics enables precise yet compliant impedance control”。

Complexity：中等偏低，physical prior + RNN residual + feedforward impedance control。
Necessity：RNN memory 对 hysteresis / partial observability 有明确问题映射。
Engineering：7-DoF real robot。
Evidence：model accuracy + generalization + actual feedback-gain reduction，把模型收益闭合到控制收益。

[V] RSS 强形态之一是“一个锐利机制 + 直接 robot-level consequence”。

======================================================================
6. Pairwise Comparison：用真实论文之间的差异学习“范围”
======================================================================

6.1 T-RO：Wijayarathne vs Pollayil

共同稳定点 [S]：
- 都有一句话可说清的核心控制问题；
- 都不要求底层工具逐个原创；
- 都有数学 formulation + online/real-robot closure；
- supporting mechanism 不被包装成多个独立大创新。

差异：
Wijayarathne problem 大：soft-contact dynamics + constrained force-motion planning + real-time
→ Method 自然复杂。

Pollayil problem 集中：在线 stiffness/damping planning + perturbation bound
→ Method 也集中。

结论 [S]：
T-RO 没有固定“应有几层算法”。真正稳定的是：
Method Complexity 必须随 Problem + Scientific Delta 的规模增长。

6.2 T-RO：Li vs Fu

共同点 [S]：
都使用很多已有思想；都通过“已有思想形成新的完整能力”构成 paper-level contribution；major components 都对应 failure。

Li：algorithm/control centric，一个主目标，支撑层围绕 learning safety/interpretability/convergence。
Fu：system centric，同时追求 force regulation + operator workload + whole-system passivity，因此 Method/evidence 更宽。

结论 [S]：
“多个模块”是否 overdesign 必须看 claim 是否也变大。

6.3 IJRR：Lachner vs UFIC

Lachner：一处 foundational inconsistency → 一个 correction → 极简 Method + 深理论 + 实机。
UFIC：force/impedance 一般统一框架 → broad robot classes / sensing modes / passive environments → 大理论体系。

共同结论 [S]：
IJRR ≠ “T-RO + 更多模块”。
IJRR 更像要求 deep/general scientific object + complete mechanism/theory/evidence。

6.4 IJRR：Piedra vs UFIC

Piedra：target-domain root cause 很具体，architecture change 直接产生巨大动态响应改善。
UFIC：问题一般、框架一般、理论广。

结论 [S]：
IJRR 可以接受 broad theoretical framework，也可以接受 target-domain persistent bottleneck + strong mechanism/evidence。
不能把“应用”自动降级，也不能把“大体系”自动升级。

6.5 ICRA Beber vs T-RO Fu

Beber ICRA 已有 tissue estimation → QP VIC → passivity → ultrasound safety 的完整链。
Fu T-RO 把 QP VIC 变成更大 shared-control/system-passivity claim 的一部分，并把 evidence 扩到 user study。

经验 [V]：
journal 相对 conference 的升级常见于：
- problem/capability scope 更大；
- strongest-prior separation 更完整；
- theory/evidence 更深更广；
而不是“再多加一个算法”。

6.6 ICRA Jin vs T-RO Pollayil

两者均涉及 online/constrained impedance selection。
Jin：focused QP VIC。
Pollayil：更一般 impedance-planning problem + inertia structure + analytical/numerical + performance/stability + 多机器人。

经验 [V]：
从 focused conference delta 到 T-RO，常见升级是 generality + mathematical closure + evidence breadth，而不是算法名字更多。

6.7 RSS Reuss vs T-RO Li

Reuss：一个短因果链，hybrid model → better feedforward → lower feedback gains。
Li：problem 更宽，需 learning + feedback + transfer boundary + theory。

共同结论 [S]：
强论文偏好 mechanism → robot-level consequence，而非 isolated metric improvement。


6.8 Paired-Lineage Comparison：比普通跨论文比较更高优先级

当存在同作者/同问题 conference→journal、specialized-journal→T-RO、early→mature version 时，必须优先比较：
- Scientific Delta 增加在哪里；
- generality 是否扩大；
- theory 是否从局部变完整；
- online/real-time 是否从演示变正式闭环；
- evidence 是否从单任务变成多条件/多机器人/系统级；
- packaging 是否从 technical point 升级为 paper-level scientific object。

[S] 这是学习真实 venue boundary 最干净的证据之一，因为 problem、作者能力和研究主线的混杂因素更少。

7. Venue Profile / Reference Distribution
======================================================================

7.1 T-RO

[V] Problem：通常是机器人控制/操作中的明确重要 failure，可一般也可重要应用。

[S] Scientific Delta：不要求每个数学工具新，但必须有相对 strongest prior 的 nontrivial paper-level delta，例如：
- meaningful generalization；
- new control relation / role；
- integrated capability；
- system-level interconnection；
- previously infeasible → real-time/executable。

[V] Packaging：当前样本常见 1 个主 Scientific Delta + 少数支撑贡献，但数量不是硬门槛。

[S] Complexity：跨度很大。稳定规律只有 complexity 与 problem/claim/delta 匹配。

[V] Theory：通常比短会议更完整，但理论种类由 claim 决定。

[S] Engineering：对 online/physical-contact claim，必须闭合到真实 controller/robot。

[V] Evidence：复杂 Method 或宽 claim 需要相应更广的 disturbance/ablation/hardware/user evidence。

经验中心：
important failure
+ defensible nontrivial Method delta
+ matched mathematical closure
+ real executable robot evidence

7.2 IJRR

[S] IJRR ≠ “T-RO + 更多模块”。

[V] 更常见至少一种：
- foundational inconsistency / deep mechanism；
- broad/general framework；
- general control understanding；
- target-domain persistent bottleneck with strong general significance/capability jump。

[S] Complexity 可极低也可很高，不构成 IJRR 身份。

[V] Theory 更常强调 mechanism explanation、generality、physical/mathematical depth 或 framework completeness。

[V] Evidence 必须与 claim 规模匹配：
foundational theory 证明物理后果；general framework 覆盖 broad settings；application bottleneck 做 direct SOTA comparison + task-level consequence。

经验中心：
deep/general scientific object
+ complete mechanism/theory/algorithm
+ evidence strong enough to support generality or capability significance

7.3 ICRA

[V] 常接受更聚焦 technical delta：new optimization formulation、constrained controller、target-domain integration、clear safety/passivity/estimation mechanism。

[S] ICRA 也可有完整多模块路线，因此不能以模块数区分 conference/journal。

[V] 相较 journal，当前样本更常见 problem scope/generalization/theory/evidence coverage 更集中。

7.4 RSS

当前 close-field 样本较少，因此仅作 [V]：
RSS 强形态之一是一个清楚、有辨识度的 algorithmic/modeling mechanism，并直接闭合到显著 robot capability/control consequence。

[R] 不得把 Reuss 的“physics + RNN”当 RSS 固定模板。


7.5 Venue Distribution Overlap（反向审计后新增）

[S] T-RO / IJRR / ICRA / RSS / RA-L / RAS / TIM 等 venue 的 Method 质量分布存在重叠。
因此：
- 一个实际发表在 RAS/TIM/RA-L 的 Method 可能在部分维度已经 T-RO-like；
- 一个实际发表在 T-RO 的 Method 也可能不是所有维度都“高于”较低 venue；
- 不能把 venue label 当监督学习中的完美标签。

正确用途是：用真实论文建立形态和范围，再判断 target readiness；而不是训练一个“标题→venue”分类器。

8. 从样本中反复出现的 Stable Patterns
======================================================================

[S1] 顶会顶刊创新的基本单位是 paper-level Scientific Delta，不是 atomic tool novelty。
MPC、QP、DDP、ADMM、RL、energy tank、sensitivity、Hertz、RNN 都可以已有；关键是是否获得新的控制角色/关系/能力。

[S2] strongest prior 必须比较“问题—机制角色—能力”，不能只看关键词。
“别人也用了 sensitivity”不能自动否定 novelty；“没人完全按 A+B+C 组合”也不能自动证明 novelty。

[S3] 合法 packaging 是发表的一部分。
真实论文会选择最有利但仍真实的 granularity：module → mechanism → relation → capability/framework。

[S4] packaging 不能创造不存在的 Scientific Delta。
同一 relation/mechanism/capability 已被 strongest prior 覆盖时，换名字、换场景、换 solver 不能救 novelty。

[S5] Method Complexity 必须与 Problem + Scientific Delta + Claim Scope 对齐。
顶刊追求的是“问题所需的最小充分专业复杂度”，不是最大复杂度或最小复杂度。

[S6] 每个 major module 至少承担一种角色：
Core Scientific Mechanism / Correctness-Stability-Safety Support / Real-time-Solver Support / Execution-Interface Support / Evidence Support。
无法映射到 paper-level claim 的 major module 是 overdesign 风险。

[S7] 简单方法若直接修复深层 bottleneck，可以比大型 architecture 更像顶刊。
Pollayil、Lachner、Piedra 都是反例。

[S8] Method 越复杂，evidence burden 越高。
多个支撑层若声称必要，应有 ablation/condition comparison/failure analysis 证明其改变 outcome。

[S9] 理论深度必须与 claim 类型匹配。
stability/passivity claim → 相应 analysis；robustness claim → robustness evidence/guarantee；real-time claim → timing/hardware evidence；clinical safety 不能由 force RMSE 代替。

[S10] Engineering Closure 是机器人控制顶刊的重要组成。
optimizer output 不是终点，要看它如何变成真实可执行 control action。

[S11] contribution point 数量不是质量。
真正标准是整篇 Method 能否用一条因果链概括。

[S12] venue 判断必须最后做。
先恢复真实 delta、复杂度、理论、evidence，再与 venue distribution 对齐；禁止先定 IJRR 再反向加模块。

9. Contribution Packaging：方法与红线
======================================================================

9.1 合法包装

P1. 提升 contribution granularity
弱：MPC + variable impedance + uncertainty + sensitivity
强而真实：future interaction uncertainty directly shapes executable feedback mechanics
前提：公式和实验真的支持后一关系。

P2. 给成熟工具新的控制角色
不是“首次使用 sensitivity”，而是“sensitivity 从分析量变成在线决定 feedback mechanics 的决策量”。

P3. 从组件列表改写为 causal chain
A 提供 X；B 建立 X→Y；C 让 Y 实时可求；D 保证 Y 可执行；
paper contribution 应是 X→Y，而不是 A+B+C+D。

P4. 选择正确 strongest-prior comparison axis
至少区分 strongest novelty prior、simpler method-fit competitor、same-venue exemplar。

P5. supporting modules 降级为必要基础设施
成熟 solver、standard IK、安全过滤若只是支撑，不要为凑贡献点单独包装。

P6. 把 capability boundary 写清楚
不是只写“RMSE 更低”，而是说明以前不能 real-time/不能处理某 uncertainty/不能保证某 property/反馈决策不受某信息影响，现在发生了什么实质边界变化；或者性能跃迁大到足以证明控制机制差异。

9.2 红线

[R1] strongest prior 已做同一 relation/capability 仍写“首次”。
[R2] 用场景替换伪装机制创新。
[R3] 用新 solver/optimizer 名字冒充 Scientific Delta。
[R4] “A+B+C 没人完全组合过”作为唯一 novelty 依据。
[R5] 只对弱 baseline，不对 strongest prior / simpler competitor。
[R6] 用复杂度、证明数量、公式数量包装创新强度。
[R7] supporting modules 全部升级成 contribution，稀释主 Scientific Delta。
[R8] narrative inflation：窄 evidence 包装成 broad framework。
[R9] capability inflation：普通指标改善写成新能力，但边界没有改变。
[R10] prior cherry-picking：忽略最接近方法族制造空白。

======================================================================
10. Complexity Alignment：判断“做重了”还是“做轻了”
======================================================================

复杂度必须条件化比较：
C_match = Method Complexity conditioned on {Problem Size, Scientific Delta, Claim Scope, Evidence Budget}

禁止：
“超过 4 个模块就是 overdesign”
“只有一个核心公式就不够顶刊”
真实样本直接否定这类硬规则。

10.1 三种已观察到的 Method 形态

Type F — Focused Method
典型：Pollayil、Lachner、Jin
1 个明确核心机制 + 少量必要支撑 + 数学/实验围绕同一机制。

Type M — Medium Integrated Method
典型：Li、Piedra、Reuss、Beber
1 个主机制 + 1–3 个直接关闭不同 failure 的支撑层 + theory/execution/experiment closure。

Type S — System / Framework Method
典型：Wijayarathne、Fu、UFIC
多模块，但 paper claim 本身也是多约束/多目标/一般框架级；每层映射到必要 system function；evidence 同步扩展。

[S] Type F/M/S 都可顶刊。错误是：Problem/Delta 只有 Type F 规模，却使用 Type S 复杂度；或 claim 已是 Type S，Method/theory/evidence 却只有 Type F。

10.2 Overdesign Signals

O1. 新增模块不改变 paper-level relation/capability。
O2. 多个 robustness/safety layer 解决同一 failure，无证据说明需要叠加。
O3. 多 solver/decomposition 只让结构更复杂，而简单 solver 已满足实时与约束。
O4. certification 强度远超 claim，且没有带来更强可发表结论。
O5. 为保复杂模块，不得不额外创造次要 problem statement。
O6. 每个模块解释很久，但整篇 Method 无法用一条因果链概括。
O7. ablation 删除模块后核心 outcome 几乎不变。
O8. 与同 problem/delta 规模真实顶刊相比 layers 显著更多，却无更大 capability/guarantee。
O9. 复杂结构主要增加计算/实现风险，没有相称 paper-level gain。
O10. supporting modules 被错误包装成多个创新点。

10.3 Underdesign Signals

U1. 声称 online/predictive，却无 real-time implementation。
U2. 声称 robust，却只有 nominal simulation。
U3. 声称 variable impedance，但优化参数未真实进入 executable feedback loop。
U4. 声称 passivity/safety，却无对应 guarantee/evidence。
U5. 声称 soft-contact-aware，但 contact model 与目标场景物理不闭合。
U6. 只给 final performance，没有 strongest-prior separation 或 mechanism evidence。
U7. problem 很大（uncertainty + safety + real-time + human），Method 只解一个子问题。
U8. journal-level broad claim 只有 conference-level narrow validation。

11. 后续审当前技术路线：必须做 Pairwise Comparison，不打分
======================================================================

禁止输出：Innovation=8/10、Complexity=7/10、Theory=9/10。
这种分数没有 reference meaning。

必须先选 Comparator Set：
A. 1–3 篇 strongest novelty prior
B. 2–4 篇 same-venue / close-field exemplar
C. 至少 1 篇 simpler method-fit competitor

逐维输出：
Dimension | Current Method | Comparator A | Comparator B | Distribution Position | Meaning

Distribution Position 优先使用：
BELOW
ALIGNED
ABOVE-BUT-JUSTIFIED
ABOVE-BUT-UNJUSTIFIED
DIFFERENT-MORPHOLOGY

必须回答：
Q1 Problem Level：当前问题与真实目标 venue 样本相比在哪一档？
Q2 Scientific Delta：相对 strongest prior 的真实增量低于/接近/高于同档论文？
Q3 Packaging：真实 delta 是否用了最强但真实 granularity？是否把 support 错写成创新？
Q4 Method Complexity：相似 problem/delta 下更轻/对齐/更重？额外复杂度换来了什么？
Q5 Necessity：是否有 Pollayil/Piedra 式更直接方案达到同一目标？
Q6 Theory：缺必要闭环，还是做了无助发表的超额证明？
Q7 Engineering：模型→decision→controller→robot 是否像真实在线顶刊一样闭合？
Q8 Evidence：证据足以防守包装后的 contribution 吗？复杂 Method 有相应 ablation 吗？

最终输出必须包含：
A. Current Position：当前 Method 最像哪 2–4 篇真实论文，为什么。
B. Venue-Aligned Aspects：哪些维度已在 reference distribution 内。
C. Below-Distribution Gaps：哪些维度低于同档样本。
D. Above-Distribution / Overdesign Risks：哪些复杂度高于同等 delta 样本且无相称收益。
E. Packaging Gap：真实 delta 是否被切碎、低颗粒度表达或夸大。
F. Minimal Convergence Direction：哪些必须补；哪些删/合并/降为支撑；主 Scientific Delta 如何收敛。
G. Venue Fit：最后才给 ICRA/RSS-like、T-RO-like、IJRR-like 或 currently below target venue，并写清基于哪些 pairwise comparisons。

11.1 Comparator Selection Protocol（强制对照选择；反向审计后新增）
---------------------------------------------------------------------

Comparator 不得由 Agent 按“最容易证明当前 Method 很强”来选。必须按以下顺序：

A. Strongest Novelty Prior（1–3 篇）
   选择在“输入信息 → 核心机制/决策 → 输出能力”关系上最接近、最可能压缩当前 novelty 的论文。
   原则：adversarial selection（对抗式选择），优先找最危险 prior，而不是最友好 prior。

B. Same-Problem Alternative（至少 1 篇）
   解决同一 root cause，但方法路线不同，用来检验当前机制是否必要。

C. Simpler Method-Fit Competitor（至少 1 篇）
   能以更简单结构解决大部分同一问题的方案；用于 overdesign / necessity 判断。

D. Same-Venue Morphology Exemplars（2–4 篇）
   与当前 problem/claim morphology 最接近，而不是随便挑目标 venue 的明星论文。

E. Paired-Lineage Comparator（若存在则必须加入）
   conference→journal / early→mature version。

每个 comparator 必须写“为什么它是对照”，禁止只列标题。

[R] 只选弱 baseline 或只选与当前路线不同的 prior = comparator cherry-picking。

---------------------------------------------------------------------
11.2 Fatal Veto / Indeterminate Logic（反向审计后新增）
---------------------------------------------------------------------

以下不是机械“打分”，而是一票否决/证据不足逻辑：

VETO-N1 Novelty Veto：
若 strongest prior 已覆盖同一 problem–mechanism-role–capability，且当前差异主要是场景、solver、参数化或叙事，则不能判 top-venue Scientific Delta 成立。

VETO-N2 Closure Veto：
若核心数学/物理链不闭合、关键变量定义不一致、控制量不能真实进入执行闭环，则无论包装多强都不能判 top-venue-ready。

VETO-N3 Evidence Veto：
若 paper-level 核心 capability 没有直接实验/理论证据，不能用辅助指标代替，则不能判 ready。

VETO-N4 Complexity Veto（软性）：
若 complexity 显著 ABOVE-BUT-UNJUSTIFIED，且引入实时/实现风险，必须先收敛；不能把“更复杂”当专业性补偿。

INDETERMINATE：
若 strongest prior、full text、关键实验或公式证据不足，输出 INDETERMINATE / PROVISIONAL，不得猜 ALIGNED。

---------------------------------------------------------------------
11.3 Claim–Evidence Matrix（反向审计后新增）
---------------------------------------------------------------------

每个 paper-level claim 必须有直接 evidence：

Claim | Required Evidence | Actual Evidence | Strength | Missing Gap

例：
- “future preview 改变 impedance decision” → preview/no-preview ablation + gain trajectory + task outcome；
- “robust to persistent parameter mismatch” → parameter-held-across-horizon tests / worst-case comparison；
- “real-time” → worst-case/percentile timing + deadline behavior；
- “passive/safe” →对应 theoretical condition + experimental energy/safety evidence；
- “system-level workload reduction” → user study，而非 force RMSE。

[S] contribution packaging 的上限由直接 evidence 的上限决定。

---------------------------------------------------------------------
11.4 Reverse-Validation Protocol（标尺自身必须持续被测试）
---------------------------------------------------------------------

每次标尺大改后至少做四类测试：

T1 Leave-One-Out Positive Test
从 Core Corpus 暂时移除一篇真实顶刊，只用剩余 distribution 判断它是否仍落在合理范围。

T2 Out-of-Sample Positive Test
使用未参与制定标尺的新近 T-RO/IJRR/ICRA/RSS 论文，看标尺是否能识别其合理 morphology。

T3 Boundary Probe
用强 RAS/TIM/RA-L/T-Mech 或 conference→journal 前版本测试是否会被无条件抬到更高 venue。
注意：实际 venue 不是绝对 ground truth，重点看标准能否指出其相对顶刊仍缺哪一层 delta/generality/theory/evidence。

T4 Counterfactual Perturbation Test
对真实顶刊做反事实：删除关键 theory/evidence/execution，或加入无关复杂层；标尺应相应降级或识别 overdesign。

[R] 如果标尺只能“解释为什么已知顶刊是顶刊”，却不能拒绝 near-miss / mutilated / overdesigned variants，则它只是事后故事，不是审计标准。

======================================================================
12. Codex 行为约束：防止读完仍跑偏
======================================================================

C1. 先读真实论文，再引用本文件规律；禁止只读本文件机械审稿。
C2. [S] 权重最高；[V] 只是经验中心；[E] 不得泛化。
C3. 不得因为某篇 IJRR 很复杂，就要求当前 Method 加复杂度。
C4. 不得因为某篇 IJRR 很简单，就自动删支撑结构。
C5. 每次 complexity 判断必须 conditioned on problem/delta/claim。
C6. 每次 novelty 判断必须恢复 strongest prior。
C7. packaging 允许且必要，但必须经过 prior check + evidence check。
C8. 任何删除必须说明删除后 scientific claim/correctness/execution 是否仍成立。
C9. 任何新增必须说明修复哪个真实 gap，以及为何需要类似深度。
C10. 不为了“更先进”把 Method 改造成更多模块。
C11. 不以 paper title / contribution list 代替公式级理解。
C12. venue alignment 是 empirical comparison，不是模板模仿。
C13. comparator 必须按 11.1 的 adversarial protocol 选择，不能自由挑有利样本。
C14. 必须区分 Author-Stated Contribution 与 Auditor-Reconstructed Delta。
C15. strongest-prior/full-text/evidence 不足时必须输出 INDETERMINATE，而不是猜测。
C16. 每个主 claim 必须建立 Claim–Evidence Matrix。
C17. 优先使用 paired-lineage evidence 学习 venue 升级，不以单篇明星论文设阈值。

13. 一页版最终经验标尺
======================================================================

【总原则】
顶会顶刊 Method 的标准不是“必须有某个算法/多少模块”，而是：
在同领域真实已发表论文的 reference distribution 下，
Problem、Scientific Delta、Packaging、Method Complexity、Theory、Engineering Closure、Evidence Closure 必须彼此匹配，并整体处于目标 venue 同档水平。

【创新性】
1. 先恢复 strongest prior；
2. 找到真实 paper-level Scientific Delta；
3. 与同领域已发表顶会顶刊的 delta 大小/性质做 pairwise comparison；
4. 允许把真实 delta 合法提升到 mechanism/relation/capability/framework 粒度；
5. packaging 不能制造不存在的 novelty；
6. “工具已有”不等于“paper-level relation 已有”；
7. “没人完全这样组合过”也不等于创新成立。

【过度设计】
1. 不看绝对模块数；
2. 看 Method Complexity 是否与 Problem + Delta + Claim Scope 对齐；
3. 同等科学增量下显著比真实顶刊更复杂，却无更大 capability/guarantee → overdesign risk；
4. paper claim 更大，因此 Method 更复杂且 evidence 同步扩展 → 可以合理；
5. 更简单方法能解决 root cause 时，复杂 architecture 需要额外证明 necessity；
6. complex Method 的 burden of ablation/evidence 更高。

【真实样本给出的关键反例】
- Pollayil T-RO：集中、相对简单也能 T-RO。
- Wijayarathne T-RO：复杂求解栈在复杂 force-motion/contact problem 下合理。
- Li T-RO：多个组件分别关闭同一 capability 的必要 failure，可以成立。
- Fu T-RO：system claim 大，系统复杂度和多维 evidence 可同步扩大。
- Lachner IJRR：一个基础 correction 足以 IJRR，深度 ≠ 复杂度。
- UFIC IJRR：大理论框架可以复杂，但作者仍主动避免不实用的过度统一。
- Piedra IJRR：直击 root cause 的直接 force-control architecture 可胜过更复杂路线。
- Beber ICRA：会议论文也能有完整 QP+estimation+passivity 链，不能以模块数区分 venue。

【最终审稿问题】
“把当前 Method 匿名放进这些真实论文中：
它在哪些维度不像真实 T-RO/IJRR/ICRA/RSS？
是科学增量不够、包装错误、复杂度失配、理论不闭合、工程没落地，还是证据不足？”

只有这个问题回答清楚，才算真正理解“顶会顶刊到底长什么样”。

15. Scope Limitation
======================================================================

本标尺是近领域 qualitative empirical reference distribution（定性经验参考分布），不是机器人学所有方向的统计定律，也不是有大样本统计置信区间的概率模型。
当前 T-RO / IJRR 样本足以支持若干高置信 [S] 规律，但不足以为每个 venue 建立机械数值阈值；ICRA/RSS 尤其需要继续扩样。

未来扩样必须：
1. 优先加入与 continuous contact / impedance / force regulation / medical contact 更接近的论文；
2. 新样本用于更新 distribution，而不是证明预设结论；
3. 若新样本与当前 stable pattern 冲突，应更新本文件；
4. 不把 distant-domain paper 用作近领域 complexity threshold；
5. 任何硬阈值都必须由真实样本统计支持，否则保持 qualitative pairwise comparison。

本次反向审计使用了：
- out-of-sample positive papers；
- paired conference/specialized-journal → top-journal comparisons；

Out-of-sample positive examples（未用于 v1.0 Core Corpus）：
A. Geiger et al., Diffusion-Based Impedance Learning for Contact-Rich Manipulation Tasks, T-RO 2026.
   按本标尺：important contact-rich gap + clear learning→energy-domain impedance relation + medium integrated complexity + real-time torque control + unseen-task generalization → T-RO-like。与真实 venue 一致。

B. Bilaloglu et al., Tactile Ergodic Coverage on Curved Surfaces, T-RO 2025.
   按本标尺：focused but nontrivial continuous-contact planning/control relation + mathematical formulation + real robot closure → T-RO-like focused morphology。与真实 venue 一致。

C. Kurtz et al., Inverse Dynamics Trajectory Optimization for Contact-Implicit MPC, IJRR 2026.
   论文明确以“surprisingly simple method + incremental innovations collectively enable real-time CI-MPC”形成 broad manipulation/locomotion capability。按本标尺应落在 IJRR 的 simple-but-general morphology，而不是因简单被降级。与真实 venue 一致。

D. Jankowski et al., Robust Pushing..., IJRR 2025.
   quasi-static belief propagation + variance-constrained trajectory optimization + contact-informed sampling + long-horizon bimanual pushing/MPC，按本标尺属于 narrow-domain but deep/general uncertainty mechanism + strong capability evidence，可进入 IJRR-like morphology。与真实 venue 一致。

Boundary probe：
E. Xue et al., RAS 2025 MPVIC。
   其 estimator + MPC/VIC + passivity + physical experiments 在“专业完整度”上已经很强。v1.0 若 comparator 选择不严格，存在被轻易判为 T-RO-like 的风险。
   这不是简单说明 RAS < T-RO，而是暴露：必须 adversarially restore strongest prior，并区分“完整工程框架”与“相对 strongest prior 的 paper-level delta”。因此新增 11.1/11.2。

Paired boundary：
F. Fu TIM 2024 → Fu T-RO 2025：从 medical QP-VIC + energy tank，升级到 shared-control + whole-system passivity + operator workload/system evidence。标尺能正确解释 journal-level scope/evidence expansion。
G. Angelini IROS 2019 → Pollayil T-RO 2023：标尺能正确识别 generality + mathematical closure + broader evidence，而非“多加算法”。

Counterfactual tests：
H. Pollayil 若额外叠加与 claim 无关的 tube/generator/certification layers：O1/O4/O8 应标记 ABOVE-BUT-UNJUSTIFIED。
I. Piedra 若删除 dynamic head-to-head comparison / task-level imaging consequence：D8/U6/U8 应使 IJRR readiness 降级。
J. Fu 若保留 broad system claim 但删除 passivity evidence / user evidence：Claim–Evidence mismatch，应 below current published morphology。

Audit conclusion：
v1.0 的核心思想正确，能够学习“顶刊形态”，但作为 Codex 自动审计标尺仍存在 comparator cherry-picking、venue-boundary overlap、author-claim anchoring、缺少 veto/indeterminate 等风险。
v1.1 通过 paired calibration + adversarial comparator selection + dual contribution reconstruction + fatal-veto logic + claim-evidence matrix + reverse-validation protocol 修复这些关键漏洞。
