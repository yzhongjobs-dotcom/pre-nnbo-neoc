# 传感器时间基准：最小修复和未解决问题

本次只修复了一个已证实的输入时间基准错误，**没有完全解决质量误差与力偏移同时存在时的窗口拒绝问题**。没有修改对象物理、抽样范围、接触模型、Method 控制算法、辨识公式、刚度估计器或门控参数；没有提交或推送 Git，也没有写入 research/ 或 project_records/。

## 已确认的错误及修复

ForceSensing 在调用 Method 前平移 col 2 编码器；ServoID.step 随后用这个平移后的编码器和原始 col 11 指令辨识伺服。两列的时间基准不同。设平移后的编码器为 y'_j=(1-q)y_j+q y_{j-1}，原始伺服为 y_{j+1}=rho y_j+(1-rho)c_j，则实际有：

`y'_{j+1}-rho*y'_j = (1-rho)*[(1-q)*c_j+q*c_{j-1}]`。

仍配原始 c_j 会引入 `q*(1-rho)*(c_{j-1}-c_j)` 的系统误差。

原复现场景真滞后为 17.746384 ms。修复前 as drawn 的在线记录为 25.485–32.086 ms，offset exact 为 26.333–33.868 ms（1 s 后的记录）；offset 0 则准确恢复真值。修复后在线记录恢复到 17.746384 ms，命令延迟为 1 拍。质量精确案例的 χ 拒绝从 445/1124 降到 0/1124（t>=1 s），支持这个输入错误的因果作用。

生产代码仅在 method3.py 增加 6 行：为在线伺服辨识保留平移、补偿前的观测，辨识函数本身保持原样。完整差异见 （临时结果，未入库）fix.diff。

## 不能把剩余问题宣称为已修复

原场景 t>=1 s 的 1124 个窗口中，as drawn 修复前：σ 精度检验拒绝 0，χ 拒绝 247，刚度落到 200 N/m 下限而被拒绝 874；修复后分别为 18、469、596。拒绝类别可重叠。不是简单的“σ 太大”，也不全是 χ。offset exact 的 χ 中位数从 15.781 降到 .284（阈值 2.680），但仍有 438 个窗口落到下限。

在同一轨迹上，以真质量重算补偿，分离质量残差和滞后/偏移残差；数据记录在 diagnostic_before/after.json 与 trajectory_*_before/after.npz。20.8 Hz 分量使用 cos/sin 加三次趋势拟合，在回归的 Z、Y 域比较，避免直接拿滤波后的力与未滤波位置比较。

另一个关键事实是，当前离散对象的加速度是 `[v(t)-v(t-Tc)]/Tc`，不是连续二阶导数。即使是平滑正弦，控制周期差分相对理想加速度也带约 `-omega*Tc/2` 的相位。固定正弦指令、无噪声、质量误差 +4.7%、滞后和偏移精确时，实测质量残差相对回归 Y 的等效增益如下（正交部分并非零）：

| 真/标定偏移 | 同相 N/m | 正交 N/m | 相位 |
|---|---:|---:|---:|
| 0 ms | 279.484 | -201.533 | -35.795° |
| 1.88 ms | 332.248 | -178.969 | -28.310° |

这是独立的固定轨迹诊断，没有把真值提供给闭环 Method。它否定了“质量残差必然仅为实数刚度偏差”的前提，**尚不足以单独解释全部闭环拒绝**。编码器端点平移后跨越指令切换点，而 _build 仍按单段伺服曲线插值，也存在剩余近似；本次没有改写这条回归路径。尚未找到可证明解决剩余崩溃、同时满足所有限制的更小修复，故停止扩大修改。
