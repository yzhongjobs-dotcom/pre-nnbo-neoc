任务：找出并修复一个小 bug：探头质量标定误差与力时间偏移同时存在时，Method 的刚度窗口几乎全被拒绝。只做最小修改，不改 Method 算法、估计器、门控阈值或对象的物理。

工作目录：experiments/rossi_failure_study/。Windows，运行 Python 用 `python -X utf8`。不要提交 Git，不要改 research/ 和 project_records/ 下的文件。

## 背景
- 对象 physics_plant3.py 的 `_tick` 中，传感器读数 = 接触力 + 真实探头质量 × 加速度（加速度 s[24] 按一个控制周期取），再按真实力时间偏移 c[34]（毫秒，1 ms 缓冲 s[25:29] 线性插值）延迟后进入 30 Hz 滤波。
- Method 只拿标定值：tool_mass_hat、tau_a_hat、sensor_delay_hat（scenes3.py 中按范围抽样）。
- method3.py 的 `ForceSensing` 在力进入 Method 前减去 tool_mass_hat × 模型加速度（由指令、编码器和标定的伺服滞后算出，按标定偏移延迟，经同一滤波器），并把编码器列（col 2）按偏移向前插值，使力和位置对齐。
- 刚度回归见 ../motion_aware_scan/common.py 的 `_build`（用 col 0 时间、col 2 编码器、col 5 力、col 11 指令；enc 模式下用伺服时间常数做周期内插值）。D⁴ 宿主见 ridge_estimator.py；门控在 Method 内（sigma ≤ rel_max·k_ref，chi 检验）。

## 现象（已复现，见 sensing_repro.py，直接运行即可）
场景：cell_scene3('shift_fast','relaxed','nominal',1,base=470900)，overrides 见脚本；候选 L。

| 情形 | 轴向 RMSE | 窗口接受率 |
|---|---|---|
| 按抽样（偏移 1.88 ms，标定 1.76；质量误差 +4.7%；滞后误差 −3%） | 4.003 | .03 |
| 偏移 0，其余照旧 | .185 | .89 |
| 偏移精确标定，其余照旧 | 1.314 | .11 |
| 质量精确，其余照旧 | .471 | .61 |
| 滞后精确，其余照旧 | 3.813 | .08 |
| 全部精确 | .135 | .88 |
| 偏移 1.0 ms，其余照旧 | 1.539 | .22 |

即：质量误差在偏移为 0 时几乎无害，偏移精确标定、质量全对时也无害，但两者同时存在时接受率崩溃。check_system3.py 中“质量误差 ±5%”的影响（+.36/+.46）和“偏移 2 ms 精确标定”（+.79）也可能是同一原因。

理论上，质量残差 Δm·a 与加速度同相；偏移精确标定时，编码器已与力对齐，残差应与 Y 同相，只等效为一个刚度误差，不应让 χ 或 σ 大到拒绝窗口。所以很可能是对齐或时间基准在某处不一致：例如 ForceSensing 中补偿或编码器平移的时间与对象实际的读数时间不一致，或者编码器平移与 `_build` 中由 col 11、伺服时间常数做的周期内插值不一致，或者某个量用了真值而不是标定值，等等。以上只是可能方向，不要预设，用数据确认。
