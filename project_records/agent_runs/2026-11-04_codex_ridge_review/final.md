## 严重问题

1. `d_estimator_replay.py:53-64`、`ridge_estimator.py:65-71`

错在：\(k\) 的 \(M\) 推导正确，但 `sigma` 与 `chi` 没有统一统计解释。对确定性二次正则，\(\hat k\) 的噪声方差应包含 \(Y'M^2Y\)，不是简单的 \(\sigma^2/(Y'MY)\)。同时，profile 后的目标函数是 \((z-kY)'M(z-kY)\)，代码的 `res@res` 只有在 \(M\) 为投影矩阵时才等价。

后果：`chi2_max`、`meas_bound` 和接受门控没有明确的标称统计含义，可能改变闭环接受率和方法排名。

怎么改：明确采用随机先验模型或确定性 Tikhonov 模型，并在回放与闭环中统一使用对应的 `sigma`、残差和自由度定义。

2. `ridge_estimator.py:29` 对比 `d_estimator_replay.py:63`

错在：闭环使用 `int(round(trace(M)))-2`，回放使用 `n-trace(S)-1`。当 order=4、\(\rho\to\infty\) 时，`trace(M)=n-4`，拟合一个 \(k\) 后的残差自由度应为 `n-5`，闭环却得到 `n-6`。有限 \(\rho\) 时还额外存在取整差异。

后果：闭环 `chi` 被系统性放大，且回放选择结果与闭环行为不一致，直接影响 `estimator_swap.py:54-58` 的门控。

怎么改：两套实现共用同一个非取整的有效自由度定义，并同步修正 `chi` 的统计解释。

3. `d_estimator_replay.py:85-98`、`106-118`

错在：窗口拟合使用 `log[0:n]`，窗口末端是 `log[n-1]`，但结果写入 `out[n]`，随后评分用 `log[n,8]` 比较。闭环估计则对应 `log[n-1]`。

后果：回放评分存在一拍错位，在刚度突变、事件和恢复时间附近会产生实质差异，不能称为严格的回放/闭环一致性。

怎么改：统一结果索引和时间戳，或者把评分目标改为同一窗口末端的 `log[n-1]`。

4. `deployable_contact.py:35-38`、`40-58`

错在：`Deployed` 的状态更新是离散递推，但 `r_c` 使用连续时间幅值。按当前 POP 参数和 20.8 Hz 计算，离散幅值约为 `1.9038`，连续幅值约为 `1.6398`，相对差约 `-13.9%`。

后果：`Zmem` 的力到运动逆变换存在显著系统性比例误差，结果不能解释为同一记忆模型的严格逆。

怎么改：逆变换使用与状态递推完全一致的离散记忆响应和归一化。

5. `deployable_contact.py:35`、`53-56`；`scenes.py:139`

错在：`Deployed` 固定 `self.kr=1e12`，相当于假设机器人串联刚度无穷大；仿真对象的 `kr` 实际随机约为 \(5\times10^4\) 至 \(2\times10^5\)。特权实现 `dynamic_gain_value.py:41` 却使用了真实 `sc['kr']`。

后果：`Deployed` 的逆变换遗漏真实的串联柔顺项，尤其影响硬组织和高刚度场景；该结果不能与真实 `kr` 下的动态逆直接比较。

怎么改：使用明确声明的可用平台刚度；若部署接口确实不提供 `kr`，则必须把该版本限定为无串联柔顺假设，不能称为同一物理逆。

6. `ridge_acceptance.py:70-83`、`55-58`；`sweeps.py:165-222`

错在：Ridge 的 `sigma_scale`、`chi_scale` 在专门的 18 点网格上重新选择；`P3_16 unit` 固定为 1，`P5_16 tuned` 使用另一套已有调参结果。Ridge 获得了额外、直接面向闭环代价的门控调参预算。

后果：Ridge 与 P3/P5 的闭环比较不是同等调参协议，Ridge 的收益可能部分来自门控尺度而不是二次先验。

怎么改：所有方法使用相同的门控调参预算、种子划分和选择指标；P3 unit 可保留为历史基线，但不能与调优后的 Ridge 作为唯一公平主对照。

7. `d_estimator_replay.py:50-64`

错在：Huber 循环最后一次更新权重后直接退出，`k`、`d` 和 `res` 仍对应旧权重，但 `dof` 已使用新权重。

后果：所有 Huber 结果的拟合量、残差和自由度不属于同一个优化状态，当前 `H_n4_f14_w32` 等结果不可作严格比较。

怎么改：最后一次权重更新后重新求解，或让自由度使用实际参与求解的权重。

## 中等问题与结论边界

8. `physics_plant.py:118-120`、`d_estimator_replay.py:106-118`

`log[:,8]` 对所有方法都隐藏且只用于评分，因此不存在真值通道泄漏，公平性基本成立。但它是用连续时间 Prony 比例和串联刚度构造的标签，不是完整闭环中的实际复数动态传递函数。尤其 memory 版本又使用了不同的 POP 分支。

后果：memory 与非-memory 的误差差异同时包含估计差异和目标定义/模型失配差异。结论应限定为“相对该评分标签的误差”。

9. `deployable_contact.py:40-58`、`estimators.py:107-111`、`variants.py:87-91`

错在：Ridge/带通估计器以 `F>.5` 判接触，运动跟踪器在 `F<.3` 才清状态。`Deployed` 没有独立的 `.5` 接触中断复位。

后果：力落在 `.3` 到 `.5` 之间时，估计器已认为窗口无效，但 `q` 记忆可能继续累积，重新接触后可能带入旧状态。

怎么改：让 `q` 的复位条件与估计器和运动跟踪器使用同一接触状态定义。

## 已查无误

- `ridge_estimator.py:26-28` 的 \(M=I-(I+\rho D'D)^{-1}\) 推导正确。
- `order=4` 时，\(D^4\) 的零空间是三次多项式。数值验证显示 \(\rho\to\infty\) 时与同窗三次投影矩阵误差趋近数值零。
- 将 \(M\) 作用于 `_build` 产生的 `z` 在数学上合理，因为 `Y` 和 `z` 使用同一力滤波权重。见 `common.py:68-83`。
- `common.py:97-121` 的窗口边界没有使用未来样本。最大访问行是 `n-1`。
- `Measured` 隐藏了真值刚度、真力、接触深度等列。见 `failure_replay.py:23-31`。
- `RidgeProjection._log` 与 `memory_response` 的离散因果滤波在小型合成序列上逐点一致；临时未完成行不会被处理。
- 回放选择种子与 Ridge 评估种子分离，`d_estimator_replay.py:197-210` 与 `ridge_acceptance.py:22-24,52-83` 没有同一场景键的重用。
- `d_structure` 使用 `BASE=410000`，评估使用其他基数，因此 `q` 没有评估种子泄漏。只是 `q` 的校准使用了 `d_structure.py:63-73` 的真值列，属于开发期特权校准，不是部署时在线读取。

## 仿真对象造成的外推风险

- `scenes.py:56-70,133-140`：组织是空间一维随机场，接触是固定几何的有限足迹；没有二维/三维接触、切向力、力矩或多接触耦合。
- `physics_plant.py:6-13,84-98`：动力学只有单个身体二阶模态，Prony 记忆是少量固定分支；Ridge 的收益可能依赖这种低阶、平滑、可预测的扰动结构。
- `scenes.py:26-47,87-129`：呼吸、最小加加速度运动、twitch、cough 和 tremor 都是人工参数化信号，不能代表真实患者运动或传感器异常。
- `scenes.py:138-139`：记忆、阻尼、反射刚度和串联刚度都以少量参数随机化，无法覆盖真实材料的状态依赖、滞回和非平稳性。
- 全部评估围绕固定 4 N 目标和 20.8 Hz 探测频率，结论不能直接外推到其他目标力、探测频率或执行器带宽。
