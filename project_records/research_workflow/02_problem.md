# 二、找真正值得研究的问题

**何时读：** 提出、修订或比较研究问题时，或者遇到强 prior、需要判断是否换题时。

例子只用于说明，不是必须照做的规定；合适就用，不合适就回到判断标准。例子出处见[逆向分析](../../research/independent_reverse_analysis_of_top_journal_methods.md)：R 编号见 §2–3，Buchli、Kang、Xue、Dyck、Jin、Fu 和 R22 见 §7。本项目的具体失败经过见[失败复盘](../research_failures_and_corrections.md)。

**核心目的：** 找到一个值得做、也做得出来的研究问题。

**判断标准：** 任务需要的能力和最强方法能给的之间，有一个真实且重要的差距，同行能认出它确有必要研究（这就是领域的 taste）。同时还要满足三点：
- 尚未解决，或者解决得不够；
- 解决后有实质的科学增量；
- 能做出来，也能验证，问题大小合适。

**怎么做：**
1. **从两种来源找。**
   - **领域公认的难题：** 来自一篇文章，最好是几篇文章共同指出的问题。汇总它们的共性，再追问两点：为什么至今没解决（难点到底在哪）；已有的尝试做到了哪一步。
   - **没人明确提出、但普遍存在的 failure：** 从应用的真实需求、物理过程和第一性原理出发，对照主流方法依赖的假设，看几种方法是否在同一条件下都出问题。最好用推导或最小实验确认这个 failure 真实存在，并且影响任务表现。
2. **到前沿边界里找线索。** 线索来自第一部分标出的文献冲突、解释缺口和边界条件。
3. **遇到强 prior 不避开，用苏格拉底式追问：**
   - 它解决了什么，在什么条件下成立？
   - 条件不成立时会怎样？
   - 作者没处理，是做不到还是没想到？
   - 这个问题解决了，会改变什么能力或认识？

   追问出的剩余痛点，往往就是更好的研究问题。
4. **表述成“具体任务 + 核心矛盾 + 希望改善的能力”。** 能力尽量定义成可测量的量。问题不能抽象到无法验证，不能小到只剩一个算法细节，也不能大到做不完。
5. **产出候选问题，交给用户选定。** 每个候选写清痛点、文献依据、现有方法的解决程度、解决后的价值和主要风险。问题可以随认识加深优化，但不能偏离核心问题；实质换题由用户决定。

**可借鉴的做法（几种常见的差距形态，并不完整）：**
- **两难：** 两个都想要的性质，已有方法只能二选一或此消彼长。例如：
  - 稳定性与精度（R13）；
  - 精度与鲁棒性（Kang）；
  - 精度与柔顺（Jin）；
  - 泛化与最优（Xue）；
  - 可操作性与接触稳定（R12）。

  可以问：哪两个性质难以兼得？最强的方法分别站在哪一边？
- **存在性证明：** 人或其他系统已经能做到，机器人还做不到（R11、R01、Buchli）。
- **先定义能力，再据此设计指标：** 例如 R12 先定义可操作性和接触稳定性。

一个问题哪种形态都不像，只要满足判断标准就成立。不要为了套用某种形态去改问题。

**AI 犯过的错：**
- **过度防守、不断缩题：** 问题越缩越小，最后变得抽象又没意义。
- **渐进偏题：** 例如从“环境变化时快速更新最优阻抗”滑到“更新价值”和“整段采集规划”，原问题被暗中替换。
- **为了让某个算法能赢而缩题。**
- **把自己的机制预设成必要前提：** 例如写“必须先区分运动和刚度”，但 DOSMAC 不区分也能处理。
- **稻草人式立题：** 例如写“已有四类方法各自必然失效”，证据并不支持。
