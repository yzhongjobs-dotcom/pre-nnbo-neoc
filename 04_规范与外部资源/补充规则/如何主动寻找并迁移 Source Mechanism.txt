# 02｜如何主动寻找并迁移 Source Mechanism

## 一、核心目标

从 **Target RMC** 主动发现未知领域中的强 Source Mechanism，而不是随机搜索相似算法。

核心链：

`Target RMC`
→ `形成 Target Mechanism Signature / 搜索约束`
→ `模型先验提出可能领域`
→ `Academic Bridge 扩展/纠正领域假设`
→ `进入候选 Domain / Paradigm`
→ `学习该领域自己的术语`
→ `搜索真实 Problem–Intervention Pair`
→ `验证 Source Causal Efficacy`
→ `Intervention-Level Isomorphism`
→ `Solution Principle`
→ `Target-Constraint-driven Necessary Adaptation`

## 二、如何找到未知领域

### 1. Model Scientific Prior

LLM 先高召回提出可能的 domain/paradigm hypotheses。

它只能形成 **Search Hypothesis**，不能作为 Scientific Evidence。

### 2. Academic Bridge Discovery

通过真实 scholarly search/read、review、citation/topic graph、相关领域桥接等扩展或纠正模型先验。

跨领域 discovery 必须真实执行；允许最后得到“未发现可信同构”。

### 3. Terminology Grounding

进入候选领域后先学习该领域描述同类机制问题的真实术语，再用这些术语搜索。

不要拿 Target 领域原词直接硬搜所有领域。

### 4. Practitioner Signal

当术语不清、问题强工程化、搜索陷入局部或需要 implementation genealogy 时，可用 GitHub / Reddit / StackExchange 等补充线索。

X 只作为 serendipity 补充，不计入 mandatory coverage。

## 三、Source Search 搜什么

不是搜：

> 哪个领域用了和我相似的算法？

而是搜：

> **哪个已有机制已经成功改变了我这里必须改变的 causal/computational variable / relation？**

正式 Source 至少应能恢复：

`Source Problem`
→ `Source Intervention`
→ `Changed Variable / Relation / Structure`
→ `Mechanism / Causal Effect`
→ `Outcome`
→ `Assumptions / Activation / Boundary`

Source RCA 只有 Evidence 足以支持时才恢复；不为满足模板编造 Source Root Cause。

## 四、怎样判断能不能迁

核心 Hard Gate：

`Target Required Mechanism Change ↔ Source Intervention`

至少检查：

* variable / relation role
* current → required change direction
* causal / intervention position
* activation condition
* Source actual effect
* assumptions / boundaries
* Target mismatch

真正必须一致的是 **intervention structure**，不是 task、algorithm、architecture、learning paradigm 或 problem story。

Isomorphism FAIL：

* 该 Source 不形成 active Candidate；
* 有新 clue → 继续 Discovery / Search；
* 暴露 RMC 错误 → 返回 RCA。

Isomorphism PASS 后抽象算法无关的 **Solution Principle**。

## 五、怎样自然迁移回来

`Source / Solution Principle`

* `Target Constraints`
  → `Assumption–Constraint Collision`
  → `Necessary Adaptation`
  → `Final Method`

只保留真正起作用的 intervention；去掉只服务于 Source task 的实现；只加入 Target 必需结构。

**改造大小本身不是创新标准。**

没有真实 constraint、assumption mismatch 或 Residual MUST，不增加额外模块。

最终删除 Source story 后仍必须得到：

`Target Failure`
→ `Root Cause`
→ `RMC`
→ `Target Constraints`
→ `Final Method`

## 六、边界

跨领域搜索默认必须真实执行，但最终 Candidate **不要求必须来自跨领域**。

如果没有可信跨域同构，而 First-Principles、Representation Transformation 或 Same-Field Mechanism 得到更强 Principle，可以继续 Method Design；不得为了“必须迁移”伪造 Source。
