2. 总体判断
======================================================================

E2E 有大量可直接服务当前任务的资产；Harness 不是本项目的必选基础设施：

- E2E 是“领域证据库 + 历史研究轨迹 + 旧方法及其失败记录”；
- Harness 是一套自建科研过程控制器，但当前设计不完善，且其能力若不优于 Academic Research Suite 就没有引入必要；
- 两者都不能替代当前 Final Method 的第一性原理推导；
- 旧 E2E 的 coverage_status=SUFFICIENT 只对其原始 Research Brief——通用 robotic impedance control 发展谱系——成立，不能自动证明当前“连续机器人超声中的 task-embedded contact-belief / executable-impedance co-adaptation”已经完成查新；
- Harness 的结构完整性也不等同于方法强度。当前正式 Method Design 仍以 Candidate Principle 为 Human Gate 前对象，存在“因果正确、字段齐全，但没有贡献级技术实体”的已知缺口。

因此，正确使用方式是：

既有证据直接复用身份、全文和已核验事实；旧综合结论重新绑定到当前问题。文献调研、分析与审查优先使用 Academic Research Suite 和当前可用的成熟工具；Harness 不进入依赖链，仅在某个具体文件确有独特、经复核的参考价值时才读取。Method 的状态、方程、作用机制、必要性命题、求解与执行闭合由当前问题重新推导。

6. 当前 E2E 对新研究问题仍不完整的部分
======================================================================

现有 E2E 对“通用 impedance control”覆盖较强，但对当前最终问题仍需定向补齐以下交叉区；仅检索 T-RO、IJRR、RSS、ICRA 及用户认可的同级顶会顶刊：

1. 连续 robotic ultrasound 中患者特异、空间变化的接触/组织属性在线估计；
2. 不进行独立逐点触诊时，scan motion 是否提供足够 structural/practical identifiability；
3. task-oriented / control-oriented / decision-oriented system identification 与 dual control；
4. 安全接触下的 active excitation、information-aware MPC 或 belief-space control；
5. normal–tangential、friction、viscoelastic 和记忆效应对 executable impedance 集合的真实影响；
6. explicit force control、robust fixed impedance、certainty-equivalent adaptive VIC 能否达到相同临床/控制能力；
7. ultrasound image/task quality 与 force/contact safety 的共同目标，避免只优化控制 proxy；
8. 实时受约束 belief/control 的最小近似，以及近似是否保持 action ordering 和 hard feasibility。

停止条件不是“又读了若干篇”，而是：每个核心 claim 有 strongest/closest prior，正反证均覆盖，且没有未检查的主方法族会改变 Problem 或 Scientific Delta 判断。

7. Harness 的结论性处置：默认不用，仅保留可选参考
======================================================================

本次已检查 GitHub harness 的 scientific-core 分支。它包含 arisctl 状态机、research-lit、idea-discovery、novelty-check、research-refine、proof-checker、formula-derivation 及多种 shared contracts，但本项目不因此采用它。

不采用为正式工作流的原因：

1. 当前任务已有 Academic Research Suite 和直接分析能力，没有必要再引入一套自建 Controller、状态机、artifact schema 与 gate；
2. 多一层流程会增加上下文、同步和状态绑定成本，却不自动提高研究质量；
3. Harness 当前 method-design-contract 仍以 Candidate Principle 为正式候选，E2E 的 METHOD_DESIGN_GAP_AUDIT.md 已指出这会放过“因果正确但没有贡献级技术实体”的方案；
4. Controller/schema 只能验证流程与字段，不能证明 Scientific Delta、Method Worthiness 或数学正确性；
5. 用户明确要求方法由当前研究问题自行调研、推导和优化，而不是由 Harness 选择或拼装。

因此新对话的默认规则是：

- 不安装、不启动、不恢复 Harness run；
- 不读取 Harness state 作为当前研究状态；
- 不要求通过 Harness Gate 才能继续；
- 不把 Harness 的 accepted/selected/final 标签带入 R15；
- 不为适配 Harness schema 改写研究问题或 Method。

仅在确有需要时，可把以下“文件中的一般原则”作为普通参考，并在使用前独立判断：

- source-admission-policy.md：来源准入与 claim-level evidence；
- reviewer-independence.md：审稿人直接读原 artifact，避免设计者引导；
- problem-necessity-contract.md：Simple Repair / residual failure 检查；
- method-refinement-protocol.md：support module 必须对应 residual gap；
- METHOD_DESIGN_GAP_AUDIT.md（位于 E2E）：Candidate Principle 不足以承担贡献级 Method Seed。

这些原则若 Academic Research Suite 已有等价或更成熟实现，则直接使用 Academic Research Suite，不再读取 Harness。其余 Harness 代码、Controller、workflow、skills 和 experiment pipeline 对当前交接不构成依赖，可忽略。

无论使用哪个工具，本项目在实验前仍必须由实际研究分析完成三个独立判断：

- Scientific Validity：因果、证据、假设、可证伪性是否成立；
- Novelty：目标域技术实体是否被 closest prior 覆盖；
- Method Worthiness：即便真实且新颖，是否足以改变可解问题、保证、能力边界或控制机制。

工具只能辅助检索、核查和审计，不能替代这三个结论。

8. 任何辅助工具都不应承担的工作
======================================================================

Academic Research Suite、Harness 或其他辅助工具都不应：

- 根据方法名自动选择 HJB、MPC、viability、belief-space、SOCP、DDP 或学习模块；
- 把旧 R15 accepted state 当成当前研究问题的证明；
- 由 schema 非空、查询数量、论文数量或 reviewer 分数宣布顶刊达标；
- 把跨域 source principle 直接贴到超声场景；
- 为追求流程闭合而保留无必要模块；
- 自动把旧 method packet 重渲染成 Final Method；
- 替研究者决定核心 Scientific Delta。

Method 设计应由以下顺序产生：

真实任务 failure
→ 为什么 fixed K / reactive VIC / explicit force control / estimate-then-optimize 不足
→ 最小 decision-relevant uncertainty 与可辨识性
→ 必要的新 control/information relation
→ 唯一目标、状态、动作和约束
→ 最小实时 realization
→ execution/fallback closure
→ strongest-prior 实体级 delta。

任何 solver、learning 或 calibration 技术只能在这个推导暴露出 residual gap 后加入。

9. 建议的新对话复用流程
======================================================================

步骤 1：读取本交接包 00—06，冻结 02 的研究问题与 04 的非回退规则。

步骤 2：检查本地 E2E 状态，记录 branch、commit、未提交文件和本地独有 source-materials；不得用 GitHub 覆盖本地新增论文。Harness 路径只作历史定位，不启动其 workflow。

步骤 3：从 E2E 迁移与当前 claim 直接相关的 Evidence Cards、全文和 strongest-prior 对比；旧 synthesis 只作为 hypothesis/negative history。

步骤 4：优先使用 Academic Research Suite，按“只看顶会顶刊”政策对第 6 节的交叉缺口做增量检索，而不是重做整个 impedance-control 综述。

步骤 5：从研究 failure 重做 Necessity 和 minimal identifiability；同时设置 explicit force、robust fixed K、certainty-equivalent adaptive VIC、generic MPVIC 四类强简化对照。

步骤 6：人工/Agent 从第一性原理构造一个 Candidate Method Seed；不调用 Harness 选择或生成 Method。

步骤 7：依次通过 Validity、Novelty、Method Worthiness、公式正确性、实时与 applied-action closure；未通过则只修对应 failure，不拼接新模块。

步骤 8：得到公式、命题、算法、复杂度和工程接口完整的 Final Method 后停止，等待用户进入实验阶段。

10. 一句话交接结论
======================================================================

E2E 足以避免从零开始，但不能证明当前新问题已经完成查新；Harness 对当前任务不是必要依赖，若不如 Academic Research Suite 就完全不用，只可偶尔参考少量通用文件。当前应复用 E2E 的全文、证据、strongest-prior 与失败历史，使用 Academic Research Suite 和独立分析补齐目标交叉区，并由“连续超声中的 decision-relevant contact ambiguity”重新推导具备 Candidate Method Seed、Novelty、Method Worthiness、数学闭合和工程可行性的 Final Method。
