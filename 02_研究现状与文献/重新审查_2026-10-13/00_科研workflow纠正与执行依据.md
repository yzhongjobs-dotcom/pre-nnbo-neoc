# 科研 workflow 纠正与执行依据

2026-10-13。依据用户连续纠正，优先于旧记录中的选题判断和实验顺序。
本文件审查研究决策过程，不宣布新的研究问题或最终方法。原方法、证明、文献和实验保留。

## 1. 对此前工作的诊断

此前反复出现的路径是：已有组件 → 找一个容易测试的任务 → 和简单方法比较 →
简单方法接近 → 缩小问题 → 发现相似 prior → 再缩小问题。
这让研究从重要的接触控制能力逐渐缩成模型修订后的策略更新，科学增量不断流失。

| 具体表现 | 判断错误 | 正确用途 |
|---|---|---|
| 看到在线辨识、阻抗优化、任务导向探索等已有工作，立即说它们不能成为研究问题 | 混淆“某种方法/能力已被研究”与“问题已被充分解决” | 回查 strongest prior 在哪些条件下有效，哪些重要条件下仍然失效，失效为什么发生 |
| 逐个排除 Hertz、MHE、QP、HJB、NEOC 等已有模块 | 用组件的新旧替代论文的科学贡献判断 | 已有模块可直接复用；审查新机制、适用边界、理论认识与实际能力 |
| 不断要求找到“必须 NNBO/NEOC”的场景 | 把特定方法的不可替代性当成研究价值的必要条件 | 检验方法是否自然解决核心困难，并提供有意义、可信的进展 |
| Q1/Q2 中强简单方法接近优化结果，就用结果推动总问题收缩 | 从局部模型和代价外推整个领域的问题价值 | 只更新已测试场景和对应机制的结论；回查模型是否保留了领域困难 |
| 强 prior 出现后加一个新的约束、延迟、估计器或认证环节 | 方法设计围绕区别于 prior，逐步变成补丁堆积 | 先解释失效成因，再让机制与成因对应；没有必要的模块不加入 |
| 为容易验证而提出 Q3“哪些模型修订值得更新策略” | 把算法链中的技术子问题提升成研究主线 | 可以是方法内部问题；只有与重要能力缺口直接相连时才有论文级位置 |
| 一找到新论文就重开选题 | 缺少稳定的问题锚点，文献新颖性审查变成无休止避让 | 在明确的问题与贡献假设上核查 prior；有证据才修订，不能因名称相似而换题 |

独立积分、强基线、公平信息和成本核对仍然有效；错误在于用这些局部检查决定
研究题目的大小，以及把方法唯一性设为顶刊问题的门槛。

最近一轮文献核查完成了 8 份现有 PDF 的带页码提取，并回查了多篇近期原文。
记录见 local_source_manifest.json 与“原文定位”。文献证据可复用；此前“已有，所以
不能作为研究问题”的推论撤回。尚未形成经过失效分析与 taste 审查的问题锚点。

## 2. 如何面对 prior

### 本领域 strongest prior

把它当作研究现状的核心地基。先还原其最强版本，包括真实输入、反馈接口、
物理假设、约束、算力、任务目标、理论和实验覆盖范围；不用弱实现替它。

然后追问：它在本领域哪些常见且重要的条件下仍有困难？失败来自信息、
物理执行、模型结构、控制机制，还是工程实现？增大算力、重新调参、采用
合理的强反馈是否可以消除？其解决机制还留下什么值得研究的能力边界？

同一个研究问题可以被多篇论文持续推进。已有工作研究过它，不构成绕开的理由。
不过，若最强工作已经解决了相同困难、提供相同能力，且候选方案没有实质进展，
则贡献不足；必须依据内容判断，不能只依据模块名称或任务名称判断。

### 其他领域 prior

优先借鉴其成熟机制，明确哪些结构和假设能迁移、哪些不能。跨领域方法可以
成为自然的方法组成部分。领域迁移有科学价值时，价值应体现在新对象产生的
实质困难、新机制/分析或重要能力，而不是把借来的方法改名。

若跨领域工作与本项目在关键数学和物理结构上完全同构，也应如实说明。
这会限定创新主张，但不妨碍使用该方法去解决有价值的领域问题。

### 模块重合

不设“模块必须新”的要求。分别判断：

- 模块是否承担核心困难所要求的职责；
- 组合是否产生可解释、可验证的新机制或能力；
- 哪部分是继承，哪部分是真正的研究贡献。

Hertz、MHE、阻抗控制、NEOC、约束和无源机制都可保留，也可替换。
取舍取决于问题和因果解释；不能为了保住原路线或回避已有模块而选择。

## 3. 正确的科研顺序

### 第一步：从研究现状找重要困难及其原因

先围绕领域能力组织文献，而不是围绕待用算法检索。
每个核心 prior 记录“已解决的能力—有效条件—未解决的困难—成因—证据”。

区分三种证据：作者明确报告的失效；多个方法共享的结构限制；本项目推断的
潜在失效。后两者需要适当的推导或复现，不能冒充文献已证明的结论。
单篇论文的 limitation 不自动等于共性 failure；必须解释它为何超出该论文。

阶段产物：能解释领域进展与剩余困难的能力地图，以及值得研究的 failure 证据。
不是“尚未有人把 A+B+C 组合起来”的空缺表。

### 第二步：提出候选问题，并先做领域 taste 自审

先说清重要任务/能力、具体困难及后果、困难成因、希望改变的能力边界。
这个问题不应依赖 NEOC 或某个现成模块的名字才能成立。

自审必须回答：

1. 本领域研究者为什么关心？有什么真实的机器人或任务后果？
2. 是否抓住一个具体、有证据的困难，而不是“未知、复杂、安全、实时”等宽词？
3. strongest prior 已经推进到哪里？我们想解决的是哪部分剩余困难？
4. 成果可能增加什么认识或能力？为何超出调参、工程提速或模块拼接？
5. 不采用预想方法，这个问题仍然成立吗？
6. 什么证据能区分真正进展与替代解释？重要条件是否来自领域而非人为造难？

taste 从本领域代表论文的问题选择、机制深度、能力进展和证据要求来校准。
不能用“已发表类似主题”否定问题，也不能用“很多模块加证明”认定达到顶刊。
应用驱动与通用控制方法两条路线分别审查；通用路线不强制依赖超声成像指标。

阶段产物：少量有明确研究价值和贡献空间的候选，以及每个候选最强的反对理由。
通过后形成问题锚点；不因后续发现一个重合模块就反复重开选题。

### 第三步：从失效成因推导自然的方法

写出机制假设：“已有方法因 X 受限，采用 Y 应改变 Z。”
先确定必须改变的机制与接口，再选择工具和已有模块。
每个方法环节对应一个必要职责；既不追求组件全新，也不自动沿用整个旧栈。

科学贡献可以是重要的能力改善、新的机制解释、一般化结果、可行范围扩展，
或具有领域意义的性能/资源进展。无需证明一个算法在所有场景不可替代。

阶段产物：完整而简洁的方法设计，以及清楚的继承部分和贡献部分。

### 第四步：用有判别力的理论或最小实验检验机制

优先验证 failure 的成因和方法是否改变它。任务条件、评价标准和强对照应来自
前两步，不能看结果后调整权重、约束或截止时间来制造优势。

局部测试不利时先定位：实现错误、模型遗漏、对照信息不公平、机制假设错误，
还是研究问题根本不成立。只修改被证据指向的层次。
方法不对则调整方法；问题的依据被推翻才调整问题；单个场景无收益不自动换题。

若简单方法在目标范围内实现相同能力，可以采用它、提炼其机制、扩展其理论，
或重新评估候选贡献；不通过人为复杂化场景来保存特定算法。

阶段产物：支持/反驳机制的证据，以及有原因的修订，而不是新的问题措辞。

### 第五步：形成完整贡献与证据

验证目标范围内的实际能力、局限、泛化和强方法比较。根据最终贡献组织论文。
顶刊价值由重要问题、实质进展和充分证据共同构成；方法链长短不是判据。

## 4. 本项目现在应如何执行

1. 继续研究现状审查；还原本领域强工作，追问其重要 failure 和可推进之处。
2. 复用已核查文献，把技术主题列表改成能力、边界和失效成因的解释。
3. 在提出新问题之前完成 taste 自审，给出具体证据与反对理由。
4. 锚定值得研究的问题后重新设计整套方法；原接触模型、估计、控制、更新和
   证明按职责复用，不能复用的再做。
5. 现有 Q1/Q2、连续 NEOC 和空间判别结果作为局部诊断与复现资源；不继续把
   “必须 NEOC”的证明作为选题前置条件，也不将 Q3 恢复为主线。

当前并未锚定新研究问题。下一份研究输出应先解释 strongest prior 的重要剩余
困难及其成因，然后给出经过 taste 自审的候选；不能先确定新的模块组合。
