# V2 与轨迹关系合成一个估计器：推导、预期与检验（2026-11-13）

把已在闭环成立的[压入关系](indentation_identity_20261112.md)写进 [V2](../active_excitation_joint_theory_v2_unified.md) 的斜率先验。本文先给推导和运行前的预期，检验结果写在第四节。

**结论（见第四节）：** 合并后的估计器在闭环中与无状态轨迹修正基本相同（跨肋不变，正常工况逐位不变），没有带来预期中对推拉误修正的抑制。原因是推拉造成的假斜率只有约 1–2 /s，与真实跨肋同量级，而 V2 趋势统计量的噪声为 2.4–3.8 /s，核对不了它。

## 一、推导

**V2 的结构。** 窗口末端为 T，z = k_T h₀ + v_T h₁ + d + ε，对 d 用 Huber-D⁴，对 v 用二次先验。冻结 Huber 权重后（M = M_W）：

\[
a=h_0^\top Mh_0,\quad b=h_0^\top Mh_1,\quad c_1=h_1^\top Mh_1,\quad m=\frac{h_0^\top Mz}{a},\quad J_v=c_1-\frac{b^2}{a},\quad \tilde v=\frac{h_1^\top Mz-b\,m}{J_v}.
\]

m 是常数窗口估计（即 Huber-D⁴ 的输出），ṽ 是剔除了水平方向后的趋势统计量，噪声方差 s_v² = σ²/J_v。记时间杠杆 τ_w = −b/a（约 0.095 s）。任意斜率估计 v̂ 给出端点估计 k̂_T = m + τ_w v̂。

**V2 原来的先验** 是 v ~ N(0, S_v²)，S_v² 由 ṽ 自己的证据调节。失效原因是 s_v 为 2.5–4.3 /s（相对），大于真实变化率，ṽ 既当证据又当估计，都被噪声淹没。

**轨迹给出的斜率。** 压入关系给出窗口信息重心到末端的刚度比 k_T/m = 1/r，r = 1 + β(y₆ − y₂₄)/C_w，C_w = F₂₄/m，β 为在线学到的预测系数。写成 V2 的斜率就是

\[
v_p=\frac{m\,(1/r-1)}{\tau_w}.
\]

**合并。** 把先验改为 v ~ N(v_p, S_p²)，S_p = ρ|v_p|（ρ 是轨迹斜率的相对不确定度）。同一个目标函数的解为

\[
\gamma=\frac{S_p^2}{S_p^2+s_v^2},\qquad \hat v=v_p+\gamma(\tilde v-v_p),\qquad \hat k_T=m+\tau_w\hat v,
\]

\[
\operatorname{Var}(\hat k_T)\approx\operatorname{Var}(m)+\tau_w^2(1-\gamma)S_p^2 .
\]

## 二、合并后改变了什么

1. **极限情形都是已知方法。** β = 0 时 v_p = 0、S_p = 0、γ = 0，输出就是 Huber-D⁴。先验很紧（γ → 0）时 k̂_T = m/r，就是无状态轨迹修正。先验很松（γ → 1）时是自由斜率的 V2。
2. **V2 的趋势统计量换了角色。** 它不再负责估计斜率，也不再负责调节先验尺度，只用来核对轨迹声称的斜率。核对的力度由 γ 决定，而 γ 随声称的斜率变大而变大：
   - 真实跨肋的典型变化率 2.5 /s：S_p = 1.25，s_v ≈ 3，γ ≈ .15。输出基本就是轨迹修正，注入的噪声约 γ·s_v·τ_w ≈ .04，可以忽略。
   - 推拉造成的假斜率（例如 9 /s）：S_p = 4.5，γ ≈ .69。后验斜率约为 .31 v_p + .69 ṽ，误修正从约 .86 降到约 .27，代价是这段时间多出约 .2 的噪声。
   - 所以它对“轨迹声称刚度在快速变化”这件事要求窗口内的证据同意，声称越大要求越强。这针对的正是轨迹修正没解决的弱点：身体运动在轨迹上与刚度变化相同。
3. **V2 的“快升慢降”尺度规则不再需要。** 此前查明它在无变化时系统偏大。
4. **不确定度有了来源。** 输出方差里多出搬运项 τ_w²(1−γ)S_p²，快速修正时自动变大，控制器的保守刚度随之留出裕度。

## 三、会引入的偏差

- **真实的最快跨肋会被注入 V2 的噪声。** 变化率 8 /s 时 γ ≈ .63，端点噪声 sd 从约 .17 升到约 .25。A_large 的 P90 变化率约 7.9 /s，所以最快的那部分跨肋会比轨迹修正略差。
- **轨迹斜率本身偏小。** β 是带收缩的预测系数，轨迹修正只去掉了约七成的滞后。合并不改变这一点，ṽ 的权重太小，补不回来。
- **ṽ 在事件起始处有偏。** 此前测得推拉起始处 ṽ 的偏差 rms 约 .8–1.2 /s，小于它的噪声，可以接受；咳嗽起始处约 6.5 /s，不在本轮范围。
- **薄覆盖层和慢扫描上没有作用。** 那里 β = 0，输出与 Huber-D⁴ 逐位相同，V2 自己的证据仍然不足。

## 运行前的预期

- **V1 跨肋不变。** 原 A_large 的 L 均值与轨迹修正（.191）相差不超过 .02，新 A_large（.261）不超过 .03；上升、下降段的平均误差相差不超过 .03，误差中位数增加不超过 .02。
- **V2 推拉的误修正减小。** 学到增益后的推拉场景（N2、N6、V6，两个方向）：远离探头方向的 L 不高于轨迹修正；最差的 N6 不高于 .40（轨迹修正 .450，基线 .333）；事件窗口的力误差 rms 不高于基线与轨迹修正的平均值。
- **V3 β = 0 的场景不变。** 原 24 个正常回合和 12 个新 A 场景 |ΔL| ≤ .003。
- **V4 机制本身。** 跨肋变化段上 γ 的均值不超过 .3；带增益的推拉事件期间 γ 的均值不低于 .5。

**预期与结果。**
- V1 跨肋不变：成立。原 / 新 A_large 的 L 均值相差 −.0004 / −.006；平均误差变化不超过 .006。
- V3 β = 0 的场景不变：成立，最大 |ΔL| 为 .0028。
- V2 推拉误修正减小：不成立。远离探头的 N6 明显改善（.450 → .267），但远离探头的 V6 变差（.114 → .124）。

**不符的原因。** 我在第二节里假设推拉会造成约 9 /s 的假斜率，这个量级估错了。由 γ = .072 和 s_v/k = 2.41 反推，事件期间轨迹声称的斜率 |v_p|/k 约为 1.3 /s：学到的 β 只有 .05–.26，窗口滞后内的轨迹变化也只有毫米量级。假斜率与真实跨肋的斜率同量级，而 V2 趋势统计量的噪声是它的 2–3 倍，所以窗口内的证据核对不了它。N6 的改善不能归因于预期的机制（那里 γ 均值只有 .16），它靠近稳定边界，单次结果不足为凭，没有做扰动检验。

**结论。**
- V2 的时变模型与轨迹修正可以写成同一个估计器，三个极限分别是 Huber-D⁴、轨迹修正和自由斜率的 V2。实际运行时 γ 约 .1，它就是轨迹修正加上有来源的不确定度。
- V2 窗口内的趋势信息在现有信噪比下既不足以估计斜率，也不足以核对轨迹给出的斜率。它只对 5 /s 以上的声称斜率有约束力。
- 合并之后，跨肋段的偏差已基本去掉（上升 −.03，下降 +.10），剩下的误差中位数（.09–.13）与平稳段（.13）相当，即主要是噪声。V2 剩下的问题不再是斜率，而是水平噪声和身体运动的混淆。
